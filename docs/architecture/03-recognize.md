# ③ 辨識

## 這個階段在做什麼

把一頁上「看得到的東西」拆開，交出一份元素清單 ElementList：文字行、圖片、形狀、表格區、背景。
只記事實與原始量測值，不下結論。分段、吸附、定案留給④與⑤。
有兩條產線，交出同一種清單：原生 PDF 直接讀檔（擷取產線），掃描、截圖、照片看影像（影像產線）。

## 各步驟細節

本節所有預設值、門檻、耗時都是初始值，待評測調整。耗時數字除註明出處者外都是估算，沒有實測。

### 共同規則

**剝洋蔥。** 影像產線先處理最可靠的東西，再處理剩下的。順序是：文字 → 表格格線 → 形狀 → 圖片 → 背景。每剝一層就得到一張遮罩，後面的步驟把已剝掉的像素當成「已解釋」，不再重複處理。例如文字筆畫不會被當成形狀去描，格線不會同時出現在表格區與形狀清單。

**不丟東西。** 看不懂的東西一律保留成圖片元素，標上類型「其他」。寧可不可編輯，不可遺失。3C.2 負責把關。

**信心值的定義（對應 R6）。** 信心值是「這個值落在容許範圍內的機率」，不是模型的原始分數。容許範圍如下表。這樣定義才能用標準答案檢驗。

| 欄位 | 「算對」的容許範圍（初始值，待評測調整） |
|---|---|
| 四角 | 每個角的偏差不超過頁寬的 0.2 % |
| 內容 | 逐字完全相同 |
| 字級原始量測值 | 相對誤差不超過 2 % |
| 顏色 | 色差 ΔE2000 不超過 5 |
| 基線 | 偏差不超過字級的 3 % |
| 類型標籤 | 完全相同 |

三條配套規則：

1. 不連乘。每個欄位的信心值只反映這個欄位自己的證據。上游步驟的不確定性用「依據」欄位指回去，不乘進來。否則多數欄位都會掉進低信心區。
2. 分輸入類型校準。每個步驟的原始分數，要用真實檔案的標準答案換算成機率，而且原生 PDF、掃描、截圖、照片四類分開換算。合成資料校出來的對照表不能直接用在照片上。
3. 誤差與信心值分開。誤差說「量得多準」，信心值說「有多大把握落在容許範圍內」。兩者都交給⑤。

**結果可重現。** 同樣的上游產物、設定檔、修正單，要得到同樣的 ElementList。模型推論固定亂數種子；每個步驟的中間結果以輸入內容的雜湊為鍵做快取，修正單重跑時只重算受影響的元素。

**AI 的用法。** 一律採編號標記法：演算法先把候選畫上編號，AI 只回答編號、標籤、或在候選中選。編號畫在外框外側並加白底，同時附一張沒有標記的原圖，避免標記遮住內容（做法建議見 research/vlm.md 3.1；在文件上的效果沒有公開數字，需自建測試集驗證）。回答用強制結構化輸出，程式端再檢查「答案是否在候選內」，不在就作廢。沒有 AI 時整條產線也要能跑完，只是中間區的項目直接交給使用者確認。

### 3.0 產線分派

**目的**　逐頁決定先走擷取產線、影像產線，或兩條都走。

**做法**　讀 SourceDoc 的每頁輸入類型：

| 輸入類型 | 分派 |
|---|---|
| 原生 PDF | 擷取產線。真假由 3A.2 細判。 |
| 掃描 PDF | 影像產線。若檔案帶隱藏文字層，把那層文字交給 3B.2 當第二意見。 |
| 截圖、照片 | 影像產線。 |
| 混合 | 兩條都走。由 3A.2 逐區分派，3C.1 合併去重。 |

分派以「區域」為單位，不是整頁一刀切。這一步只產生初版，3A.2 才定版。

**輸入與輸出欄位**　輸入：SourceDoc 的每頁輸入類型、PDF 內嵌資料索引。輸出：產線分派表（初版）。

**信心值依據**　SourceDoc 輸入類型本身的信心值；索引是否自相矛盾（例如標為原生 PDF，但文字物件數為 0）。

**常見失敗與對策**　①判錯類型。對策：類型與索引矛盾時兩條產線都跑，多花時間但不會漏。

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| route.run_both_on_conflict | 開 | 類型與索引矛盾時兩條都跑 |
| route.min_type_confidence | 0.9 | 低於此值視為矛盾 |

**可單獨升級的點**　分派規則表可以依真實檔案的誤判統計調整，不影響其他步驟。

### 3A.1 走訪頁面物件

**目的**　把 PDF 頁面內容攤開成一份「繪製紀錄」，3A.2 到 3A.7 都讀它。

**做法**

- 主引擎用 PDFium（BSD-3-Clause 加 Apache-2.0），經 pypdfium2 的底層介面呼叫。它是查到唯一授權可用、又同時能讀逐字屬性、向量路徑、圖片、頁框並能渲染的引擎（見 research/pdf.md）。
- 頁面物件分文字、路徑、圖片、漸層、表單物件五類（見 research/pdf.md 3.1 第 4 條）。表單物件（Form XObject，一組可重複使用的繪圖指令）要走進去，矩陣一路相乘。
- 每個物件記：種類、合併後的變換矩陣、繪製順序號、外框、裁切路徑、所屬圖層名稱、所屬表單物件。
- PDFium 公開介面缺的，用 pikepdf（MPL-2.0）補：圖層清單與預設開關、字型字典有沒有 Unicode 對照表與內嵌字型檔、圖片的軟遮罩、透明度設定（見 research/pdf.md 建議第 2 點）。
- 座標用 PageSpec 給的矩陣換成頁面相對座標。PDF 的 y 軸朝上，相對座標 y 軸朝下，這裡統一。
- PDFium 不是執行緒安全，逐頁平行要用多行程（見 research/pdf.md）。

**輸入與輸出欄位**　輸入：原始檔案、頁碼、PageSpec 的矩陣。輸出：繪製紀錄（本階段內部用，不進 ElementList）。

**信心值依據**　直接從檔案讀到的值，來源類型是「精確擷取」，信心值 1.0。以下情況下調：檔案經過修復；PDFium 與 pikepdf 讀到的物件數對不上；用到的函式回傳失敗。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 單頁物件極多（地圖、工程圖可達十萬個以上） | 超過上限時，路徑整頁併成一個向量圖組，只保留文字與圖片為獨立元素。 |
| 需要的 PDFium 函式多數標為實驗性，官方保留更動權利（見 research/pdf.md） | 鎖定 PDFium 版本，升級前跑回歸測試。 |
| 物件在頁框之外 | 照樣讀出，可見性標「頁框外」，列入隱藏內容清單。 |
| 直排文字、Type 3 字型、只靠預定義對照表的中日韓字型 | PDFium 對這些困難檔案的表現沒有實測（見 research/pdf.md 查不到的事第 5 項），需查證。先靠 3A.2 的交叉檢查攔截。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| pdf.max_objects_per_page | 200,000 個 | 超過就把路徑併成向量圖組 |
| pdf.max_form_depth | 16 層 | 表單物件巢狀上限 |
| pdf.page_timeout | 60 秒 | 單頁逾時就整頁改走影像產線 |

**可單獨升級的點**　① 加第二引擎做交叉比對：pdfminer.six（MIT）或純 Rust 的 hayro（Apache-2.0 或 MIT，作者自述介面仍在變）。② 付費改用 MuPDF 商業授權，一次呼叫就給齊隱藏文字類型、圖層、繪製順序；價格未公開（見 research/pdf.md）。

### 3A.2 假原生細判與逐區分派

**目的**　有些 PDF 看起來是原生的，其實文字不可信。找出來，把那些區域改派影像產線。

**做法**　核心是一個交叉檢查，叫「渲染後偵測」：把頁面渲染成影像，跑一次 3B.1 的文字偵測，再把偵測到的文字框與檔案裡的文字物件逐一配對。

| 畫面上偵測到文字 | 檔案裡有文字物件 | 判定 | 處理 |
|---|---|---|---|
| 有 | 有，且可見 | 真文字 | 走擷取產線。每種字型抽幾行，拿辨識結果比對內容。 |
| 有 | 沒有，該處是向量路徑 | 外框字（文字已轉成圖形） | 該區改走影像產線。輸入影像改用高解析度單獨渲染這些路徑，底是乾淨的。 |
| 有 | 沒有，該處是圖片 | 圖片裡的字 | 圖片佔滿頁面：整頁掃描圖，走影像產線。一般圖片：交給 3B.8 判歸屬。 |
| 有 | 有，但不可見 | 隱藏 OCR 文字層 | 該區走影像產線。隱藏層的文字交給 3B.2 當第二意見，不直接採用。 |
| 沒有 | 有，但不可見 | 隱藏內容 | 不輸出，列入隱藏內容清單。 |
| 沒有 | 有，且可見 | 字太小、對比太低，或偵測漏掉 | 仍採用擷取結果，加低信心旗標。 |

三種假原生各自的細判：

1. **隱藏 OCR 文字層。** 最直接的訊號是文字渲染模式為 3（不可見），PDFium 讀得到（實測，見 research/pdf.md 3.13）。但只看這個不夠，還有三種看不到的情形：不透明度為 0、被後畫的不透明圖片蓋住、被裁切路徑裁掉。PDFium 沒有現成函式判斷「被蓋住」，要自己用繪製順序加外框重疊去算（見 research/pdf.md 建議與查不到的事第 7 項；做法未實測，需查證）。Producer 字串只當先驗，不當判據。
2. **外框字。** 判據就是上表第二列：畫面有字、檔案沒有文字物件、該處有路徑。輔助統計：大量小型封閉路徑成列排列、高度一致、同色。被判為外框字的路徑從 3A.4 的形狀清單扣掉，不重複輸出。
3. **缺 Unicode 對照表。** 三個訊號：字型字典沒有對照表（pikepdf 讀得到）；PDFium 逐字回報「Unicode 對照有誤」（實測，見 research/pdf.md 3.13 第 10 點）；讀到的字落在私用區或是替代符號。處理方式是「字碼對照重建」：位置、字級、顏色照樣取自檔案（精確），內容改由辨識取得。同一個字型的同一個字碼在全文件出現多次，對所有出現處的辨識結果投票，一致率夠高就重建整張對照表。內容的來源類型記為「量測」，不是「精確擷取」。投票不一致的字，該行改走影像產線。

**混合頁。** 一頁內真文字與含文字的圖片並存時，逐區決定：文字物件走擷取產線；每張夠大的內嵌圖片各跑一次文字偵測，有字就依上表第三列處理。兩條產線的結果在 3C.1 合併，重疊時擷取產線優先。

**輸入與輸出欄位**　輸入：繪製紀錄、頁面渲染影像、SourceDoc 的索引與 Producer。輸出：產線分派表（定版）、隱藏內容清單、字碼對照重建表（內部用）。

**信心值依據**　文字框與文字物件的配對率；抽樣行的內容吻合率（真文字應接近 100 %）；三個訊號是否一致；字碼投票的一致率。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 檔案同時有可見文字與一份重複的不可見文字（部分軟體為了無障礙加的） | 兩者位置重疊且內容相同時，只留可見的那份。 |
| OCR 文字層的渲染模式不是 3，而是畫在圖片底下 | 靠「被蓋住」判斷。在該判斷做好之前，靠 Producer 先驗加「整頁有一張大圖」的組合攔截。 |
| 只有部分頁面或部分區域做過 OCR | 逐區判定，本來就不是整頁一刀切。 |
| 偵測模型漏掉小字，誤以為是隱藏內容 | 判為隱藏內容前，先確認該文字物件的渲染結果與背景確實沒有差異。 |
| 有對照表但內容是錯的（字型被加密混淆、合字對應錯） | 抽樣辨識比對能抓到；吻合率低於門檻就視同缺對照表。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| fake_native.check_every_page | 開 | 每一頁原生 PDF 都做渲染後偵測 |
| fake_native.render_dpi | 150 dpi | 交叉檢查用的渲染解析度 |
| fake_native.outline_render_dpi | 600 dpi | 外框字單獨渲染的解析度 |
| fake_native.match_iou | 0.5 | 文字框與文字物件算配對成功的重疊比例 |
| fake_native.sample_lines_per_font | 10 行 | 每種字型抽幾行比對內容 |
| fake_native.min_content_match | 98 % | 抽樣吻合率低於此值，該字型視為對照表不可信 |
| fake_native.scan_image_cover_ratio | 60 % | 圖片佔頁面面積超過此值且含字，視為整頁掃描圖 |
| fake_native.vote_min_occurrences | 3 次 | 一個字碼至少出現幾次才投票 |
| fake_native.vote_agreement | 90 % | 投票一致率門檻 |

**可單獨升級的點**　① 「差分渲染」判斷被蓋住：把物件拿掉再渲染一次，畫面沒變就是看不到。準確但慢，只對可疑物件做。② 外框字的字形還原：同一個外框形狀重複出現，可以只辨識一次。

### 3A.3 文字物件合併成文字行

**目的**　從檔案讀出每個字，合併成文字行，交出與影像產線相同格式的文字行元素。

**做法**

1. **逐字讀取。** PDFium 逐字提供：Unicode、緊貼外框、原點、字級、字型名稱與旗標、字重、填色、描邊色、變換矩陣、所屬文字物件的渲染模式（見 research/pdf.md 3.1 第 2、3 條；旋轉文字的字級實測正確）。角度以矩陣為準，不用 PDFium 回報的角度值（實測方向定義容易混淆，見 research/pdf.md 3.13 第 4 點）。
2. **合併成段。** 相鄰的字若字型、字級、顏色、渲染模式、基線都相同，併成一段。
3. **合併成行。** 同一條基線上（偏差不超過字級的 5 %）、方向相同、間隙不超過上限的段，併成一行。間隙超過上限就切成兩行，並記入「同基線群組」，讓④判斷是表格儲存格、定位點還是分欄。
4. **補空白。** PDF 常常不存空白字元，只靠位置留空。間隙超過門檻就記一個空白，並把間隙寬度存進「行內間隙」。PDFium 自己補出的字（行尾換行等）會標示為「引擎補出」，不當成檔案內容（實測，見 research/pdf.md 3.13 第 3 點）。
5. **清理字型名稱。**
   - 子集字型（只內嵌用到的字）的名稱前面有六個大寫字母加一個加號的亂碼前綴，例如 AAAAAA+WenQuanYiZenHei-0。去掉前綴，記「是子集」。
   - 部分產生器從字型合集載入時會在名稱後加「-序號」（實測，見 research/pdf.md 總表 ReportLab 列），一併去除。
   - 中文字型名稱可能以位元組跳脫或舊編碼儲存，要解碼。
   - 把 PostScript 名稱拆成字族與樣式，例如 TimesNewRomanPS-BoldItalicMT 拆成 Times New Roman、粗體、斜體。
   - 用一張別名表對到常見顯示名稱（例如 PMingLiU 對新細明體、DFKai-SB 對標楷體）。這張表要自己建，需查證各名稱的實際寫法。
   - 原始字串原封保留一份。
6. **字級與變形。** 字級取矩陣換算後的有效值。矩陣橫向與縱向比例不同時，記水平縮放（精確）。字距由相鄰字原點的距離減去該字的前進寬度得出（精確）。PDFium 公開介面是否能直接讀字距、詞距、水平縮放的設定值，查證紀錄沒有列出，需查證；用原點反推不依賴這些函式。
7. **特殊情形。**
   - 同一串字在極小位移下畫兩次：是假粗體，併成一份並標記。位移較大且顏色不同：是陰影，記入特效。
   - 渲染模式為「填色加描邊」：記描邊色與線寬，粗細另加標記。
   - 渲染模式為「當作裁切路徑」：文字被用來裁圖片（圖片填字），記入特效並標「不可量測」。
   - 合字（兩三個字母合成一個字形）：一個字形對多個字元，字元清單照字元記，字框共用。
8. **字型候選清單。** 原生 PDF 只有一個候選：檔案裡的字型名稱，來源類型「精確擷取」。另記是否內嵌。「比對用字型」先留空，或由別名表預填字寬相容的開放字型。

**只讀名稱與量度，不取出字型程式。** 內嵌字型的字寬表與上伸下伸值可以從字型字典直接讀（見 research/fonts.md 3.8 第 6、7 點），足夠做字寬比對。把內嵌字型取出來存檔或用在別處，法律風險高，不做（見 research/fonts.md 4.5）。

**輸入與輸出欄位**　輸入：繪製紀錄中的文字物件、字碼對照重建表、PageSpec 矩陣。輸出：文字行的全部欄位。其中筆畫遮罩留空，標「可由檔案重繪」；字級另存 pt 原值。

**信心值依據**　值來自檔案的欄位為 1.0。下調的情形：內容來自字碼對照重建；字型未內嵌（畫面外觀取決於閱讀器的替代字型，但名稱仍可信）；字型名稱無法對到別名表；合併成行時間隙接近門檻。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 一行字被拆成每字一個文字物件，或一個文字物件橫跨多欄 | 合併只看幾何與屬性，不看物件邊界。 |
| 表格同一列的各格被併成一行 | 間隙上限加上「不跨過直線」的規則：中間有直向格線就切開。 |
| 字的繪製順序不是閱讀順序 | 行內依基線方向的位置重排。跨行的順序不在這裡處理，在④。 |
| 字型名稱是無意義代號（例如 F1、T3） | 名稱標「不可用」，改由 3B.5 以渲染影像求候選。 |
| 顏色是 CMYK 或特別色 | 另存原值。轉 sRGB 需要色彩描述檔，選哪一份、其授權為何，需查證。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| pdftext.baseline_tol | 字級的 5 % | 視為同一條基線的容許偏差 |
| pdftext.max_gap | 1.5 個字級 | 超過就切成兩行 |
| pdftext.space_gap | 0.25 個字級 | 超過就記一個空白 |
| pdftext.dup_offset | 字級的 5 % | 小於此位移的重複字串視為假粗體 |

**可單獨升級的點**　① 用 PDF 內的字寬表與伺服器上的開放字型逐字比對，替每個比對用字型算出「字寬吻合率」，交給⑤與⑦。② 別名表持續擴充。

### 3A.4 向量路徑合併成形狀

**目的**　把檔案裡的向量路徑變成形狀元素。簡單的要能當原生形狀編輯；複雜的整組保留，不拆碎。

**做法**　真實困難是數量：一張圖表或插畫可能有上千條路徑。全部變成獨立形狀，輸出檔會無法編輯。所以先分群，再決定每一群的去向。

1. **辨識基本幾何。** 逐條路徑檢查線段結構：四條直線且兩兩垂直是矩形；四段特定比例的曲線是圓或橢圓；四直線加四圓弧是圓角矩形；單一線段是線。這是解析判斷，不是擬合，容許誤差極小。
2. **合併成對的填色與描邊。** 同一個幾何先填色再描邊，畫了兩次，併成一個有填色也有線條的形狀。
3. **細長矩形改記為線。** 許多 PDF 用細長的填色矩形畫線，表格格線尤其常見。符合條件的改記為線，線寬取矩形的短邊。
4. **分群。** 依四個線索把路徑歸成群：同屬一個表單物件；繪製順序相連；外框重疊或相鄰；共用同一個裁切路徑或圖層。
5. **決定去向。**

| 群的狀況 | 去向 |
|---|---|
| 路徑少，且多為基本幾何 | 每條各成一個形狀元素，可編輯。 |
| 路徑多，或線段總數多 | 整群成為一個圖片元素，類型「向量圖組」。附無損的向量片段，另附一張渲染好的點陣圖備用。 |
| 已被 3A.2 判為外框字 | 扣除，不輸出為形狀。 |
| 已被 3B.10 認領為表格格線 | 歸屬指向表格區，只存一份。 |

6. **裁切路徑。**

| 情形 | 處理 |
|---|---|
| 裁切範圍比物件大，或就是頁框 | 忽略。 |
| 矩形裁切套在圖片上 | 記成圖片的裁切視窗。 |
| 圓形、圓角矩形裁切套在圖片上 | 記成圖片的外形。 |
| 任意形狀裁切 | 記成遮罩；套在向量群上的留在向量片段內。 |
| 裁切套在文字上 | 記入文字特效。 |

7. **漸層。** 線性與放射漸層記成填色參數（起訖點、色標）。網格漸層、函式漸層、圖樣填色沒有對應的可編輯形式，渲染成點陣圖，記錄「已轉點陣」。PDFium 公開介面是否能讀出漸層參數，查證紀錄沒有列出，需查證；讀不到時用 pikepdf 直接讀漸層字典。
8. **透明度。** 固定不透明度記成欄位（精確）。混合模式不是「正常」的，記下原值，交給⑥決定是否降級。帶軟遮罩的透明群組沒有可編輯形式，整群走「向量圖組」。混合模式與軟遮罩的讀取同樣要靠 pikepdf 追蹤繪圖狀態，PDFium 的對應能力需查證。
9. **看不到的路徑。** 沒有填色也沒有描邊的路徑只是用來裁切，略過。

**輸入與輸出欄位**　輸入：繪製紀錄中的路徑與漸層物件、外框字清單。輸出：形狀元素（路徑、填色、線條、不透明度、混合模式、裁切）；圖片元素（類型為向量圖組，含向量片段與備用點陣圖）。

**信心值依據**　幾何與顏色來自檔案，為 1.0。基本幾何的辨識附解析誤差。分群是推論，信心值依四個線索的一致程度；分群的最終決定權在④。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 白色不透明矩形蓋住底下的內容（塗白） | 被蓋住的物件照樣讀出，可見性標「被遮住」，列入隱藏內容清單，預設不輸出。 |
| 圖表被拆成數百個可編輯小形狀 | 路徑數門檻擋下，整群保留。 |
| 一個標誌被分成兩群 | 分群線索加上「同色系且外框相鄰」。仍分錯時由修正單合併。 |
| 向量圖組在簡報軟體中無法以向量呈現 | 備用點陣圖已備妥。用哪一份由⑥決定。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| vector.max_paths_editable | 50 條 | 一群超過此數就整群保留 |
| vector.max_segments_editable | 500 段 | 一群線段總數超過就整群保留 |
| vector.group_gap | 頁寬的 0.5 % | 外框相距小於此值視為相鄰 |
| vector.thin_rect_max_width | 3 pt | 細長矩形改記為線的寬度上限 |
| vector.thin_rect_min_aspect | 20 倍 | 細長矩形改記為線的長寬比下限 |
| vector.fallback_dpi | 300 dpi | 備用點陣圖的解析度 |

**可單獨升級的點**　① 向量圖組內再辨識出圖表結構，升級成可編輯圖表。② 分群規則可獨立替換成學習式方法。

### 3A.5 內嵌圖片擷取

**目的**　取出檔案裡的點陣圖，連同遮罩、裁切、實際解析度。

**做法**

1. **位置。** 圖片的擺放矩陣換成四角，可表示旋轉、傾斜、翻轉。
2. **像素。** 能保留原始壓縮資料就保留（例如 JPEG 原封不動），不重新壓縮。PDFium 可取原始與解碼後的位元組、濾鏡、像素尺寸（見 research/pdf.md 3.1 第 5 條）。
3. **遮罩。** PDFium 只給「套用遮罩後」的結果，拿不到遮罩本身；pikepdf 能直接讀軟遮罩，並能合成進透明通道（實測與文件，見 research/pdf.md 需求對照與 3.5 第 4 條）。兩者並用，得到帶透明通道的圖。
4. **實際解析度。** 像素數除以擺放後的實際尺寸，橫向與縱向分開算。低於門檻加品質旗標。
5. **裁切。** 見 3A.4 第 6 點。預設把被裁掉的像素實際切除，不帶進輸出檔。理由：被裁掉的部分是使用者看不到的內容，帶出去等於洩漏隱藏內容。
6. **拼接。** 有些產生器把一張圖切成多條橫帶存放。相鄰、解析度相同、邊緣對齊的圖片物件併成一張。
7. **類型。** 用 3B.7 與 3B.9 的同一套分類器標上照片、插畫、圖表等類型。
8. **含文字的圖。** 夠大的圖片跑一次文字偵測，結果交給 3A.2 做混合頁分派。
9. **單色模板圖。** 只有一個位元、以填色畫出的圖（掃描文字常以這種形式存放），視為掃描內容，改派影像產線。

**輸入與輸出欄位**　輸入：繪製紀錄中的圖片物件、裁切紀錄。輸出：圖片元素（四角、裁切影像、類型、外形與透明遮罩、實際解析度、原始編碼與裁切視窗）。

**信心值依據**　位置與像素為 1.0。類型標籤的信心值來自分類器，依 R6 分開校準。拼接的信心值依邊緣對齊誤差。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 特別色或多色版的圖片，pikepdf 不轉檔會報錯（見 research/pdf.md 3.5 第 4 條） | 改用 PDFium 渲染後的點陣圖，來源類型降為「量測」。 |
| CMYK 的 JPEG | 保留原檔，另存一份轉成 sRGB 的版本。色彩描述檔的選擇需查證。 |
| 一張看起來是單一圖片的東西，實際由多張圖、遮罩、向量繪圖合成（見 research/pdf.md 3.5 第 4 條） | 依 3A.4 的分群規則併成一群；無法乾淨合併時整群渲染成一張圖。 |
| 內嵌在內容串流裡的小圖 | PDFium 是否把它列為圖片物件，需查證。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| pdfimg.min_text_check_px | 短邊 200 px | 小於此尺寸的圖不做含字檢查 |
| pdfimg.stitch_tol | 0.5 px | 拼接時邊緣對齊的容許誤差 |
| pdfimg.keep_cropped_pixels | 關 | 是否把被裁掉的像素帶進輸出 |
| pdfimg.lowres_warn_dpi | 100 dpi | 實際解析度低於此值加品質旗標 |

**可單獨升級的點**　圖片類型分類器可獨立更換或重訓。

### 3A.6 圖層、可見性與背景判定

**目的**　記錄每個元素的前後順序與所屬圖層，找出畫面上看不到的物件，並指認哪個物件是背景。

**做法**

- **繪製順序。** 原生 PDF 的前後順序就是繪製順序，直接記為圖層初判，來源類型「精確擷取」。
- **圖層。** PDF 的圖層（可選內容群組）用 pikepdf 讀清單與預設開關；物件屬於哪個圖層，由 PDFium 的內容標記讀出（實測，見 research/pdf.md 3.1 第 10 條）。注意 PDFium 的「物件是否啟用」函式不是圖層可見性，不能用（實測，見 research/pdf.md 3.1 第 11 條）。
- **預設關閉的圖層。** 其中的物件照樣讀出，可見性標「圖層關閉」，預設不輸出，列入隱藏內容清單。
- **圖層名稱保留。** Illustrator 與 InDesign 匯出的 PDF 常帶有意義的圖層名稱，對④的群組判斷有用。
- **背景判定。** 繪製順序最底、覆蓋頁面面積超過門檻的物件（整頁色塊、整頁圖片）指認為背景。原生 PDF 的背景不需要生成：文字與其他元素底下的像素本來就在檔案裡，生成區域為空。

**輸入與輸出欄位**　輸入：繪製紀錄、pikepdf 讀到的圖層設定。輸出：每個元素的圖層初判、可見性、來源圖層名稱；背景元素；隱藏內容清單的增補。

**信心值依據**　繪製順序與圖層歸屬為 1.0。「被遮住」是計算結果，信心值依遮擋物的不透明度與覆蓋比例。背景指認的信心值依覆蓋面積與是否位於最底。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 圖層可見性由複合條件決定 | 只處理基本條件；複雜條件視為可見並加旗標。 |
| 兩個圖層同名 | 不用名稱比對，改用檔案內的物件參照。 |
| 背景由多個物件拼成（多條色帶） | 全部指認為背景的組成部分；也可留作形狀，由④決定。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| layer.respect_default_off | 開 | 預設關閉的圖層不輸出 |
| bg.fullpage_cover_ratio | 90 % | 覆蓋頁面超過此比例才可指認為背景 |
| occlusion.diff_render | 關 | 是否用差分渲染判斷被遮住 |

**可單獨升級的點**　差分渲染（見 3A.2 升級點）。

### 3A.7 註解與表單欄位

**目的**　PDF 有一類可見內容不在頁面內容裡，而在「註解」裡：超連結、螢光標示、便利貼、印章註解、表單欄位的值。漏掉它們，畫面就對不上。

**做法**

- 用 pikepdf 讀頁面的註解清單（pikepdf 可讀寫任何字典，見 research/pdf.md）。PDFium 專用的註解介面本次沒有查證，需查證。
- 對應規則：

| 註解種類 | 記成什麼 |
|---|---|
| 超連結 | 涵蓋範圍內文字的「超連結」欄位。 |
| 螢光標示、底線、刪除線註解 | 涵蓋範圍內文字的裝飾欄位。 |
| 表單欄位 | 欄位的值記成文字行，加標記「表單值」。 |
| 印章、手繪、圖章 | 圖片元素，類型依內容標註。 |
| 便利貼與彈出視窗 | 預設不輸出，列入隱藏內容清單。 |

- 交叉檢查用的頁面渲染，要與這裡的處理一致：這裡有處理的註解才畫進去，否則⑦會把差異誤判為錯誤。

**輸入與輸出欄位**　輸入：原始檔案的註解字典。輸出：文字行的超連結與裝飾欄位；新增的文字行與圖片元素。

**信心值依據**　註解的範圍與內容來自檔案，為 1.0。註解範圍對到哪些文字是幾何計算，依重疊比例。

**常見失敗與對策**　註解的外觀與其記載的屬性不一致（外觀串流被改過）。對策：以渲染出來的外觀為準，屬性只當提示。

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| annot.enabled_types | 超連結、螢光標示、底線、刪除線、表單欄位 | 處理哪些註解種類 |
| annot.text_overlap | 50 % | 註解範圍與文字重疊超過此比例才掛上去 |

**可單獨升級的點**　表單欄位升級成 Word 的內容控制項，屬於⑥的工作；這裡只要把類型記清楚。

### 3B.1 文字偵測

**目的**　找出每一行文字的四角。文字是整頁最可靠的訊號，所以最先剝。

**做法**

- **模型。** 用 PP-OCRv6 的偵測模型，以 ONNX Runtime 執行，以 RapidOCR 為起點或自己包一層。程式與權重都是 Apache-2.0；其中 PP-OCRv6 權重的授權是間接證據，上線前要有人親自打開官方模型卡確認（見 research/ocr.md）。伺服器用 medium 級。它輸出每行四個頂點，可表示傾斜的行。Tesseract 的行框是水平矩形，不合用（見 research/ocr.md 需求對照）。
- **切塊與多尺度。** 300 dpi 的 A4 是 2,480 × 3,508 px。整頁縮小送進模型會漏掉小字。做法：原尺寸切成互相重疊的方塊各跑一次；另外把整頁縮小再跑，專抓比方塊還大的標題字。同一行在多塊、多尺度重複出現時，依共線與重疊合併。
- **方向。** 逐行判斷是否上下顛倒或轉了 90 度。整頁方向是②的事。
- **偵測框不是量測依據。** 偵測框有鬆有緊。四角在 3B.3 會用筆畫遮罩重新擬合成墨跡緊框；字級不從框高算。
- **切行修正。** 一行內間隙超過上限就切開，並記入同基線群組，規則與 3A.3 相同。
- **二次機會。** 3C.2 找到像字的殘餘墨跡時，回到這裡對那一小塊補做一次。

**輸入與輸出欄位**　輸入：工作影像、品質遮罩。輸出：文字行的四角（初值）、旋轉角、偵測分數。

**信心值依據**　偵測分數；多個尺度是否都偵測到；之後的辨識分數（讀不出字的框多半是誤偵測）；筆畫遮罩的品質。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 漏偵測：極小字、低對比、孤立的單一字（頁碼、座標軸刻度）、超大標題、藝術字 | 多尺度；3C.2 的二次機會；仍漏掉的由⑦開修正單補框。 |
| 誤偵測：紋理、條碼、虛線、手寫筆跡 | 辨識分數低且筆畫統計不像字，就撤銷，像素退回殘餘。 |
| 兩欄的字被連成一行 | 切行修正。 |
| 彎曲的行 | 四角框不住。基線擬合殘差大時，標為沿曲線排列（見 3B.6）。 |
| 直排 | 第一版不支援：整塊當圖片，附上辨識文字，書寫方向欄位標「直排」。PP-OCRv5 官方明列支援直排，PP-OCRv6 的文件沒有提（見 research/ocr.md），需查證。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| det.model | PP-OCRv6 medium | 偵測模型 |
| det.tile_size | 1,280 px | 切塊邊長 |
| det.tile_overlap | 20 % | 相鄰方塊的重疊比例 |
| det.scales | 1.0、0.5、0.25 倍 | 多尺度 |
| det.score_min | 0.5 | 偵測分數下限 |
| det.min_text_height | 6 px | 低於此高度的框加低解析度旗標 |

**可單獨升級的點**　① 換偵測模型，介面只有「影像進、四角出」。② 改用多邊形輸出處理彎曲文字；PP-OCR 偵測模型的多邊形輸出格式本次沒有查證，需查證。③ 用自有的海報資料微調。沒有任何公開數字說明現成模型在海報上的表現（見 research/layout.md 查不到的事第 3 項）。

### 3B.2 文字辨識

**目的**　讀出每一行的內容，並保留「還有哪些可能」。檔案急救市場最重視文字正確，所以不確定的地方要留下證據，不能悄悄猜。

**做法**

1. **模型。** PP-OCRv6 的辨識模型。單一模型同時支援繁體中文與英文，混排不必切換（見 research/ocr.md 3.1 第 4 條）。
2. **自己寫解碼層，取得候選字。** 模型把一行影像由左到右分成許多小步，每一步對字典裡每個字給一個機率。現成函式庫只取每一步的第一名，再把整行平均成一個分數，候選字就丟了（見 research/ocr.md 3.1 第 11 條）。我們直接讀模型輸出的完整機率表，每一步取前幾名，就得到每個字的候選與分數。這一層函式庫沒有現成功能，要自己寫（見 research/ocr.md 3.1 第 12 條）。候選裡包含「空」，表示「這裡可能根本沒有字」，用來表達多讀或漏讀。
3. **字框先求近似。** 函式庫的字框是由小步的位置推算的，誤差沒有任何量化資料（見 research/ocr.md 查不到的事第 5 項）。所以這裡的字框只當初值，3B.3 用筆畫遮罩精修。
4. **長行切片。** 很長的行送進模型會被橫向壓扁。超過寬高比上限就切成互相重疊的片段，各自辨識後接起來。
5. **候選擴充表。** 一張固定的對照表，把模型前幾名沒列到、但確實常混淆的字補進候選：繁簡對應字、異體字、形近字（己已巳、未末、日曰）、數字與字母（0 與 O、1 與 l 與 I）、全形與半形標點、各種橫線（一、—、–、-）。這是查表，不是推論。
6. **升級階梯。** 依信心值閘門逐層升級，過了門檻就停。

| 層 | 做法 | 工具 |
|---|---|---|
| 0 | 第一名機率高於門檻，直接採用。 | 小模型 |
| 1 | 第二意見。Tesseract 5.5（Apache-2.0，內建候選字輸出）再讀一次；若有隱藏 OCR 文字層也納入。逐字對齊，不一致處成為候選。 | 小模型 |
| 2 | 幾何消歧。全形或半形看字寬；各種橫線看長度、高低位置、粗細。 | 演算法 |
| 3 | 重繪消歧。3B.5 求出字型與字級後，把每個候選字畫出來與筆畫遮罩比，取最像的。 | 演算法 |
| 4 | 大型 AI 在候選中選。給行影像、前後文、每個不確定位置的候選編號。只能回答編號或「都不是」。 | 大型 AI |
| 5 | 交給使用者確認。 | 人工 |

7. **不靠上下文的內容。** 數字、金額、日期、編號、網址、電子郵件，語意上猜不出來，AI 也無從判斷。這類字串跳過第 4 層，只用影像證據；仍不確定就直接到第 5 層。
8. **空白。** 拉丁文字之間的空白數量、中文與英文之間的空隙，以量到的間隙為準，不以模型輸出的空白為準。

**AI 的界線。** AI 不得改寫原文。程式端檢查每個回答都是合法的候選編號，否則作廢。經 AI 選定的字，來源類型記「AI」。這條界線有依據：研究指出視覺語言模型會依語言習慣改寫畫面上的字，而且原文錯誤少的時候最容易被改壞（見 research/vlm.md 第 74 至 78 條）；所以預設不做全文校正，只做有約束的選擇（見 research/vlm.md 3.4）。Tesseract 的繁體中文準確度沒有官方數字，對照片的表現也沒有資料，先只用在掃描與截圖（見 research/ocr.md 備選一）。

**成本。** 把一頁所有不確定的行拼成一張圖、一次問完。以 Claude Sonnet 5.5 為例，每百萬 token 輸入 2 美元、輸出 10 美元，每張圖的 token 數為「寬 ÷ 28」與「高 ÷ 28」各自無條件進位後相乘（見 research/vlm.md）。一張 1,000 × 1,000 px 的拼圖約 1,296 個影像 token，輸入成本約 0.003 美元（依該公式推算）。回應時間與各模型的資料保留條件沒有查到（見 research/vlm.md 查不到的事第 8、14 項），需查證。

**輸入與輸出欄位**　輸入：行的四角、工作影像（行裁切並拉正）、隱藏文字層（若有）、語言提示。輸出：內容；字元清單（字、近似字框、信心值、候選字與分數與來源、字的類型、是否需使用者確認）。

**信心值依據**　第一名的機率；第一名與第二名的差距；兩個引擎是否一致；重繪消歧時兩個候選的相似度差距；是否屬於易混字組；該行的解析度（x 字高有幾個像素）。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 繁體字被讀成簡體字；罕用字不在字典裡 | 候選擴充表加重繪消歧。PP-OCRv6 字典的繁體字涵蓋範圍未知（見 research/ocr.md 查不到的事第 4 項），需查證。 |
| 廠商公布的準確度不能當預期值（同一模型的繁中準確率在兩份官方文件是 93.29 % 與 74.7 %） | 自建繁體中文加英文的測試集，自己量（見 research/ocr.md 3.1 第 7 條）。 |
| 解析度太低 | 不對文字區做生成式放大，筆畫可能被改掉（見 research/image.md 3.2）。加低解析度旗標，採用門檻收緊。 |
| 整行其實不是字 | 整行分數低就撤銷該行。 |
| AI 服務無法使用 | 跳過第 4 層，直接到第 5 層。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| rec.model | PP-OCRv6 medium | 辨識模型 |
| rec.topk | 5 個 | 每一步保留幾個候選 |
| rec.accept_prob | 檔案急救 0.98；靈感模板 0.95 | 直接採用的門檻 |
| rec.user_confirm_below | 0.80 | 升級後仍低於此值就交使用者 |
| rec.second_engine | 掃描與截圖開；照片關 | 是否啟用第二意見 |
| rec.ai_enabled | 開 | 是否允許第 4 層 |
| rec.ai_batch_lines | 20 行 | 一次呼叫最多問幾行 |
| rec.max_aspect | 寬高比 25 | 超過就切片辨識 |
| rec.min_xheight | 8 px | x 字高低於此值加低解析度旗標 |

**可單獨升級的點**　① 加同家族的第二辨識模型 PP-OCRv5_server_rec，共用偵測結果與解碼程式（見 research/ocr.md 備選二）。② 用小型文件解析模型（PaddleOCR-VL-1.6 為 Apache-2.0、GLM-OCR 權重為 MIT，見 research/ocr.md 備選三）重讀困難區塊，只把它讀到的字加進候選，不採用它的座標。③ 解碼層改成保留多條整行讀法，候選更完整。

### 3B.3 筆畫遮罩

**目的**　在每個文字框內，把「筆畫」與「底」分開，得到一張遮罩。之後的顏色、字級、字型、粗細、背景修補，全部以這張遮罩為準，不再回頭看偵測框。

**做法**

1. **取樣範圍。** 行的四角向外擴一圈，從工作影像裁出並拉正。
2. **分出兩群顏色。** 依困難度逐級升級：

| 級 | 情況 | 方法 |
|---|---|---|
| 1 | 底色均勻 | 框內顏色分成兩群（筆畫、底），在兩群連線上取門檻。 |
| 2 | 光線不均或漸層底 | 局部二值化（門檻隨位置變動）。OpenCV 延伸模組有 Niblack、Sauvola、Wolf、NICK 四種（Apache-2.0，見 research/image.md 2.1 第 9 條）。 |
| 3 | 字壓在照片或花紋上 | 顏色分成三到五群，挑「最像字」的那一群：筆畫粗細一致、位置與辨識出的字數吻合。 |
| 4 | 以上都失敗 | 筆畫分割模型。現成的 Hi-SAM 程式碼是 Apache-2.0，但權重沒有明文授權，只有以 HierText 訓練的那組可能可用，需法務確認（見 research/image.md 1.5）。長期做法是用開放字型合成資料自己訓練（見 research/image.md 3.5）。 |

3. **深色字或淺色字。** 兩群之中，形成細長連通結構、較少碰到框邊的那一群是筆畫。
4. **存覆蓋率，不存黑白。** 每個像素存「筆畫佔這個像素的比例」，0 到 255。算法是把像素顏色投影到「底色到筆畫色」的連線上。邊緣像素的覆蓋率透露了邊界在像素內的位置，量測因此可以到亞像素。
5. **分出不是字的東西。** 很長的橫線（寬度超過兩個字級、高度很薄）先挑出來，當作底線或刪除線的候選，交給 3B.6；穿出文字框的長線不屬於這一行，退回殘餘；細小雜點刪除。這一步必須在量測之前做，否則底線會被算進字的高度。
6. **精修字框。** 把遮罩的墨跡塊與已知字串對齊：中文每字一塊，拉丁文字以詞為單位（相連的字母不強行切開）。
7. **重新擬合四角。** 以遮罩的緊貼外框取代偵測框。
8. **估計模糊程度。** 量筆畫邊緣從 10 % 升到 90 % 的寬度，供 3B.5 重繪比對時做同等模糊。

**解析度與儲存成本**

- 遮罩的解析度等於工作影像的解析度，每頁存一張，每一行記自己在其中的矩形範圍。
- 小字（x 字高低於門檻）量測時把局部裁切放大 2 到 4 倍再算。放大只在計算當下做，不存。
- 成本估算（未實測，待量測）：

| 項目 | 300 dpi 的 A4（2,480 × 3,508 px，約 870 萬像素） |
|---|---|
| 8 位元遮罩，未壓縮 | 約 8.7 MB |
| 8 位元遮罩，無損壓縮後（文字以外全是 0） | 估 0.2 到 0.8 MB |
| 1 位元遮罩，未壓縮 | 約 1.1 MB |
| 1 位元遮罩，壓縮後 | 估 0.03 到 0.1 MB |

- 20 頁的文件約 4 到 16 MB，遠小於工作影像本身。遮罩隨使用者檔案一起在 30 天後刪除（R7）。
- 預設存 8 位元。儲存吃緊時可降成 1 位元，代價是邊緣定位從亞像素退回 0.5 px，3B.5 的誤差公式要跟著放大。
- 原生 PDF 不存遮罩。需要時可由檔案只渲染文字物件得到。

**輸入與輸出欄位**　輸入：行的四角、工作影像、內容與近似字框。輸出：筆畫遮罩；四角（墨跡緊框，定版）；字元清單的字框（精修）；底線與刪除線候選；鄰近背景的取樣範圍；模糊程度；遮罩品質分數。

**信心值依據**　筆畫與底的色差；兩群是否分得開；筆畫粗細是否一致；墨跡塊數與字數是否吻合；用到第幾級方法。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 空心字、外框字 | 出現三群顏色且其中一群形成等寬的環。標記為特效，遮罩取外輪廓。 |
| 帶陰影的字 | 第三群顏色的形狀與筆畫相同但有位移。陰影另存，不併入筆畫。 |
| 漸層填色的字 | 筆畫顏色沿行方向連續變化。遮罩照做，顏色標「非單色」。 |
| 字色與底色太接近 | 品質分數低，升到下一級；仍失敗就整行標「遮罩不可靠」，後續量測全部降信心值。 |
| 印刷網點讓底色看起來有顆粒 | 依品質遮罩先做對應網點週期的平滑，再分群。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| mask.margin | 行高的 30 % | 文字框向外擴的範圍 |
| mask.bit_depth | 8 位元 | 遮罩位元深度 |
| mask.upsample_below | x 字高 12 px | 低於此值量測時局部放大 |
| mask.upsample_factor | 2 到 4 倍 | 局部放大倍率 |
| mask.min_contrast | ΔE 10 | 筆畫與底的最低色差，低於此值升級 |
| mask.rule_min_length | 2 個字級 | 橫線長於此值列為底線或刪除線候選 |
| mask.speck_max_area | 字級平方的 0.5 % | 小於此面積的雜點刪除 |

**可單獨升級的點**　第 4 級的筆畫分割模型可獨立訓練與更換；介面只有「影像進、覆蓋率遮罩出」。

### 3B.4 文字顏色

**目的**　量出文字的顏色，同時記下緊鄰的背景色。

**做法**

1. **取筆畫核心。** 把遮罩向內縮幾個像素，只留筆畫中央。邊緣像素是筆畫色與底色的混合（反鋸齒），不能取。
2. **取中位數。** 核心像素逐色版取中位數，比平均不怕雜點。同時記離散程度，當作誤差。
3. **筆畫太細、沒有核心時。** 像素顏色都落在「底色到筆畫色」的連線上。取連線遠端的穩健極值（例如第 95 百分位）當筆畫色，誤差放大。
4. **鄰近背景色。** 取遮罩外擴一圈的環狀區域的中位數與離散程度。用途有三：判斷螢光標示（3B.6）、給背景修補參考（3B.13）、算對比。
5. **非單色。** 核心顏色呈兩群以上，或沿行方向連續變化：依顏色切段（3B.6），或標「非單色」。
6. **顏色的可信程度隨輸入類型不同。** 無損截圖的顏色接近原值。掃描受掃描器影響。照片受光線影響，②做過白平衡後仍只是估計，信心值設上限。把顏色歸到主題色是⑤的工作。

**輸入與輸出欄位**　輸入：筆畫遮罩、工作影像、色彩空間。輸出：顏色（sRGB 值、誤差、取樣像素數、是否非單色）；鄰近背景色（值、離散程度）。

**信心值依據**　核心像素數量；核心顏色的離散程度；輸入類型；該區是否落在品質遮罩的陰影或反光內。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 截圖用了次像素渲染，字的邊緣帶紅藍色邊 | 橫向每三個像素平均後再取色；只取核心。 |
| JPEG 壓縮把細筆畫的顏色沖淡 | 只取最粗的筆畫；誤差放大。 |
| 字壓在照片上，背景色不均 | 鄰近背景色記「不均勻」，不給單一值。 |
| 黑字在照片裡變成深灰或偏色 | 照實記錄量到的值。是否歸為純黑由⑤決定。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| color.erode | 筆畫粗細的 25 %，至少 1 px | 向內縮的量 |
| color.min_core_pixels | 30 個 | 核心像素少於此數改用極值法 |
| color.extreme_percentile | 第 95 百分位 | 極值法取的位置 |
| color.ring_inner、color.ring_outer | 2 px、6 px | 鄰近背景取樣環的內外距 |
| color.photo_confidence_cap | 0.8 | 照片輸入的顏色信心值上限 |

**可單獨升級的點**　以整頁的白點與黑點做二次色彩校正；可獨立加入，不影響其他步驟。

### 3B.5 字級與字型聯合求解

**目的**　量出每一行（每一段）的字級原始值與誤差，並列出字型候選。兩件事一起解，因為它們互相決定：知道字型才能從行寬算字級，知道字級才能比對字型。

名詞：em 是一個字級的長度，12 pt 的字 1 em 就是 12 pt。x 字高是小寫字母 x 的高度。前進寬度是一個字佔用的橫向寬度，含兩側留白。字面高是漢字墨跡的高度。

**做法**

(1) **備好字型量度索引。** 離線用 fontTools（MIT）把候選字型庫的每個字型讀一遍，存下：每個字的前進寬度與墨跡外框、x 字高、大寫字高、上伸下伸、字面高比例、各字重的筆畫粗細、斜體角度（各項量度在字型檔的位置已實測，見 research/fonts.md 3.8）。候選字型庫就是伺服器上裝的開放授權字型：Noto Sans TC、Noto Serif TC、LXGW WenKai TC、Liberation、Carlito、Caladea、Gelasio 等，全是 SIL OFL 1.1（見 research/fonts.md 4.1）。可變字型要先切成各字重的靜態檔，否則預設會拿到最細的那一級（見 research/fonts.md 4.1）。

(2) **從筆畫遮罩取量測值。** 行寬 W（第一個字墨跡左緣到最後一個字墨跡右緣）、x 字高、大寫字高、字面高、相鄰全形字的中心間距。哪個字拿來量哪一條線，由已知內容決定：x、a、e 量 x 字高；H、E 量大寫字高；g、p 不拿來定基線。

(3) **對每個候選字型算兩個獨立的字級估計。**

- 由行寬：字級 = W ÷（這串字在該字型、1 em 時的墨跡寬度）。後者用 HarfBuzz 排一次字得到，含字與字之間的微調。HarfBuzz 是 Old MIT 授權，Python 綁定 uharfbuzz 是 Apache-2.0（見 research/fonts.md 1.6）。
- 由 x 字高：字級 = 量到的 x 字高 ÷（該字型的 x 字高比例）。例如 Carlito 的 x 字高比例是 978 ÷ 2,048 = 0.478（實測，見 research/fonts.md 3.10）。
- 兩個估計越接近，這個字型越像。吻合度取兩者比值的對數絕對值，越小越好。

這個比值等於「量到的寬高比」除以「字型的寬高比」，與解析度、比例尺都無關。所以字型比對不受 R4（尺度不可知）影響。

(4) **重繪比對。** 取吻合度最好的前幾個候選。用 FreeType 以求得的字級把同一串字畫出來，依 3B.3 量到的模糊程度做同等模糊，對齊後與筆畫遮罩比相似度（逐字算重疊比例，再按面積加權），並比筆畫粗細。FreeType 要選 FreeType License 那一邊，產品文件要註明使用（見 research/fonts.md 1.6）。

(5) **輸出候選清單，不選定。** 每個候選附量度吻合分數、重繪相似分數、此候選下的字級估計。字級原始量測值取各項證據的加權平均，權重是各自誤差平方的倒數。

這就是「檢索加重繪比對」：檢索靠量度索引查表，比對靠重繪。全程不需要訓練分類器。

(6) **量度等價群。** 字寬相容的字型靠量度分不出來，也不需要分。例如 Liberation Sans 與 Arimo，可列印的 ASCII 95 個字元前進寬度全部相同（實測，見 research/fonts.md 3.10 第 4 點）。它們合成一個候選，「推論字型名稱」列出整群，挑哪個名字由⑤依來源軟體判斷。Liberation、Carlito 與微軟原字型是否逐字同寬，查證時沒有微軟字型可比（見 research/fonts.md 查不到的事第 14 項），需查證。

(7) **兩個欄位分開（對應 R2）。** 每個候選同時記「推論字型名稱」與「比對用字型」。前者可以是伺服器沒有的字型（例如 Calibri）；後者是伺服器上實際拿來算與畫的字型（例如 Carlito）。兩者不可混用。伺服器不能安裝微軟字型與台灣商用字型（見 research/fonts.md 1.4、1.5）。

**中文捷徑**

全形字在沒有調字距時，每個字的前進寬度都是 1 em。所以相鄰字的中心間距就等於字級，與字型無關。實測 Noto Sans TC、Noto Serif TC、LXGW WenKai TC 的漢字與全形標點都是 1 em（見 research/fonts.md 3.10）。微軟正黑體、新細明體、標楷體沒有實測（見 research/fonts.md 查不到的事第 15 項），需查證。

設有效解析度為 D（dpi）。1 px 等於 72 ÷ D pt；字級 S pt 的字，1 em 等於 S × D ÷ 72 px。

| | 300 dpi | 96 dpi |
|---|---|---|
| 1 px 等於 | 72 ÷ 300 = 0.24 pt | 72 ÷ 96 = 0.75 pt |
| 12 pt 的字，1 em 等於 | 12 × 300 ÷ 72 = 50 px | 12 × 96 ÷ 72 = 16 px |
| 只量一個字（兩個邊緣各差 0.5 px，合計 1 px） | ±0.24 pt，即 ±2.0 % | ±0.75 pt，即 ±6.3 % |
| 量整行 21 個字（首尾中心相隔 20 個間距） | ±0.24 ÷ 20 = ±0.012 pt，即 ±0.1 % | ±0.75 ÷ 20 = ±0.038 pt，即 ±0.3 % |

通式：一行有 N 個全形字，首字中心到末字中心的距離是 (N − 1) 個間距。這段距離的量測誤差仍是 1 px 左右，與 N 無關。所以字級的誤差是 1 px ÷ (N − 1)。N 為 21 時，就是單字量測的二十分之一。

更好的做法是用全部字的中心做直線擬合，不只用首尾。每個中心的定位誤差為 σ 時，間距的誤差是 σ × √( 12 ÷ ( N × (N² − 1) ) )。N 為 21 時是 0.036 σ，約二十八分之一，而且不怕首尾剛好量錯。

這對產品的意義：Office 的字級多半落在 0.5 pt 的格點上，要分出 12 pt 與 12.5 pt，誤差必須小於 0.25 pt。96 dpi 下只量一個字做不到（±0.75 pt），量整行做得到（±0.04 pt）。

三個但書：

1. 量得到的是墨跡中心，不是字身中心。每個字的墨跡中心相對字身中心有偏移。偏移有正有負，擬合時大致抵銷；標點的偏移大而且同向，擬合前先排除。偏移的實際大小沒有量過，需實測。
2. 平均之後，隨機誤差已經小於系統誤差。系統誤差不會因平均變小：②攤平後殘餘的比例誤差（0.5 % 的比例誤差在 12 pt 上是 0.06 pt）、調過字距、以及比例尺本身。
3. 捷徑量的是「字間距」。只有在沒調字距、全形等寬時才等於字級。其餘情形見下表。

③存的是相對值：字級相對值 = 1 em 的像素數 ÷ 頁寬的像素數。pt 值由⑤乘上 PageSpec 的頁寬得到。比例尺的不確定性不併入③的誤差，分開交給⑤。

**例外處理表**

| 情況 | 怎麼偵測 | 對策 |
|---|---|---|
| 調過字距 | 中文：由間距推得的字級，與由字面高推得的字級不合。拉丁：對所有候選字型，由行寬推得的字級都比由 x 字高推得的大（或都小），且字與字的空隙一致地偏大或偏小。 | 字級改以高度類證據為準（x 字高、大寫字高、字面高）。間距與字級的差記成「字距原始量測」。行寬不參與字型評分。加旗標「調字距嫌疑」。 |
| 左右對齊造成詞間拉寬 | 拉丁：詞內字距正常，詞間空白比候選字型的空白寬很多。中文：相鄰幾行左右邊緣都對齊，而各行間距略有不同。 | 拉丁改成逐詞求解：每個詞各算一次字級，取中位數，不用整行寬。中文取相鄰行中最小的間距，並以字面高交叉檢查。加旗標「左右對齊嫌疑」，由④⑤用段落證據確認。 |
| 字被水平縮放 | 每個字的寬高比都比候選字型大或小同一個倍率，橫筆與豎筆的粗細比也跟著變。調字距只改空隙，不改字身，可據此區分。 | 倍率記成「水平縮放原始量測」。字級以高度為準。 |
| 伺服器沒有該字型 | 所有候選的量度吻合分數與重繪相似分數都低於門檻。 | 不硬選。字級只用與字型無關的證據：中文用間距；拉丁用該類別字型的 x 字高比例範圍，誤差相應放大。候選清單只給類別，並附量到的特徵（寬高比、x 字高與大寫字高之比、筆畫粗細比、有無襯線），讓⑤挑最接近的替代字型。加旗標「無吻合字型」。 |
| 一行只有兩三個字 | 字數低於門檻。 | 誤差公式自動變大（除以 N − 1）。所有高度證據都用上。候選字型的分數差距不採信。加旗標「字數不足」，⑤可借同段其他行的結果。 |
| 比例寬度的中文字型 | 相鄰字中心間距忽大忽小（全形等寬時幾乎固定）。 | 不用間距捷徑，改走第 (3)(4) 點的候選字型求解。加旗標「比例寬度嫌疑」。 |
| 連續標點被擠壓成各半個字寬 | 標點前後的間距約為半個字級。 | 擬合時排除標點與相鄰的間距。 |
| 中英混排的自動間隔 | 中文與拉丁之間有固定的小空隙。 | 中文段與拉丁段分開量，不跨段擬合。中文段求出的字級可直接用來檢驗拉丁段的字型。 |
| 沒有小寫字母（全大寫、純數字） | 由已知內容直接得知。 | 改用大寫字高或數字高。 |
| 截圖的小字被對齊到整數像素，字寬不是線性縮放 | 輸入類型為截圖，且 1 em 小於門檻。 | 放寬行寬證據的誤差；重繪比對時加試「對齊像素」的畫法。各軟體實際的畫字方式沒有查證，需查證。 |
| 藝術字、變形字 | 基線擬合殘差大，或字高沿行變化。 | 不量，標「不可量測」。 |

**輸入與輸出欄位**　輸入：筆畫遮罩、內容與字框、字型量度索引、有效解析度、攤平方式。輸出：字級原始量測值與誤差（附每種證據各自的值與誤差：間距、行寬、x 字高、大寫字高、字面高）；字型候選清單；字距原始量測；水平縮放原始量測；例外旗標。

**信心值依據**　各項證據彼此是否一致；字數；該行的局部解析度；例外旗標的數量；候選第一名與第二名的分數差。信心值只描述「相對值量得準不準」，不含比例尺。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|

| 內容辨識錯，行寬跟著算錯 | 內容信心值低的字不參與計算。內容被修正單改過後，本步驟對該行重跑。 |
| 幾套字型長得很像（各家黑體） | 給整群，不硬分。 |
| 一行混用兩種字型 | 3B.6 分段後，各段回來各自求解一次。 |
| 曲面攤平讓行的局部比例不均 | 依 PageSpec 的攤平方式放大誤差。 |

**可單獨升級的點**　① 字型類別分類器。字型庫變大時用來先縮小候選範圍。目前沒有授權乾淨又能辨識中文字型的現成模型，要用開放字型合成資料自己訓練（見 research/fonts.md 4.3）。② 量度資料庫：只存字寬數字、不存字形，涵蓋伺服器不能安裝的常見字型（微軟正黑體、新細明體、Calibri、Aptos）。資料從哪裡來、是否合法，需法務確認。③ 第二輪精修：選定候選後，用字形外框修正每個字的墨跡中心偏移。

### 3B.6 其他文字屬性與行內分段

**目的**　量出字級與字型以外的屬性，並把一行內屬性不同的部分切成段。量不出來的要明講。

**做法**　每種屬性的量法與輸出如下。

| 屬性 | 怎麼量 | 輸出 | 量不出來時 |
|---|---|---|---|
| 粗細 | 筆畫粗細（遮罩上到最近邊界的距離，取筆畫中線處的中位數）除以 x 字高或字面高，再與候選字型各字重的同一比值比較。 | 筆畫粗細比（原始值）；粗細候選。 | 軟體硬加的假粗體與真粗體分不出來，照量到的粗細記。 |
| 斜體 | 把遮罩往各個角度反向推斜，找出直筆畫最集中的角度。 | 傾斜角（度）與誤差。 | 真斜體與硬推斜的差別，靠斜體候選字型的重繪比對；中文多半是硬推斜。Office 硬推斜的角度沒有查證，需查證。 |
| 底線 | 3B.3 挑出的橫線候選，位於基線下方不遠、長度與一段文字相符、顏色通常與文字相同。 | 有無、位置、粗細、顏色、涵蓋的字元範圍。 | 與表格格線或分隔線難分時，兩種可能都記，並在表格區與形狀清單中不重複計入。 |
| 刪除線 | 橫線穿過 x 字高中段，且連續跨過字與字的空隙。中文的橫筆畫不會連續跨過空隙，可據此區分。 | 同上。 | — |
| 螢光標示 | 該段的鄰近背景色與頁面背景不同，且背後有一塊緊貼行高、左右對齊字緣的色塊。 | 色塊顏色、對應的色塊元素編號、緊貼程度。 | 是「螢光標示」還是「一個矩形」，③只記事實，由④⑤決定。 |
| 上下標 | 行內某些字明顯較小，且基線上移或下移。 | 段的基線位移與字級比例（原始值）；提示「可能是上標或下標」。 | — |
| 基線 | 由已知內容挑出不帶下伸部的字，對它們的底緣做穩健直線擬合。純中文行沒有拉丁基線，改記漢字的中線。 | 兩個端點；基線種類（拉丁基線或漢字中線）。 | 從漢字中線換算到拉丁基線需要字型的基線表，由⑤處理。 |
| 行內多種字級或顏色 | 逐字量顏色、字高、筆畫粗細、傾斜，找出屬性改變的位置。用「改變點偵測」決定切點，每多切一段要有足夠的證據。 | 段清單，每段有自己的字元範圍與屬性。 | 字型的切換至少要一個詞或兩個漢字才判斷，單一個字不切。 |
| 旋轉文字 | 角度取自基線擬合。裁切拉正後量測，座標再用保留下來的變換轉回頁面。 | 旋轉角；四角本身已含旋轉。 | — |
| 沿曲線排列 | 各字中心不在一條直線上，二次曲線擬合明顯比直線好。 | 曲線路徑（各字中心連成的折線）、內容、以字高量的字級。 | 第一版不還原成可編輯文字：預設以圖片呈現，內容附在旁邊，標「沿曲線，未還原為可編輯」。 |
| 陰影 | 有一份形狀與筆畫相同、位置偏移、顏色不同的墨跡。 | 位移、顏色（估計值）。 | 模糊半徑量不準，標「估計」。 |
| 外框（描邊） | 筆畫外圍有一圈等寬的第二種顏色。 | 外框顏色與寬度（估計值）。 | — |
| 光暈、漸層填色、花紋填色、立體效果 | 偵測得到存在，參數量不出來。 | 特效類型；標「不可量測」。 | 文字內容照樣保留。原貌可隨時由四角從工作影像裁出，⑥可選擇以圖片呈現。 |
| 浮水印式文字 | 字級很大、對比很低、常帶旋轉、壓在其他內容之下。 | 圖片類型另標「浮水印」，並保留辨識內容。 | — |

**分段的原則。** 寧可少切。逐字量測有雜訊，照單全收會把一行切得很碎。每多一個切點都要付出「代價」，只有屬性差異夠大、夠穩定才切。分段後，3B.4 與 3B.5 對每一段各跑一次。

**輸入與輸出欄位**　輸入：筆畫遮罩、內容與字框、3B.4 與 3B.5 的結果、底線與刪除線候選。輸出：段清單；粗細斜體；基線；裝飾與特效；旋轉角；曲線路徑；上下標提示。

**信心值依據**　該屬性的量測值離判斷門檻有多遠；段的長度（字數）；遮罩品質；重繪比對是否支持（例如粗體候選比常規候選更像）。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 一行被切得太碎 | 提高切點代價；段的最短長度設下限。 |
| 帶下伸部的字把底線切斷，底線被當成幾小段 | 底線候選先跨字連接再判斷。 |
| 中文的長橫筆被當成刪除線 | 必須連續跨過字間空隙才算。 |
| 粗體與常規體的差別在低解析度下量不出來 | 筆畫粗細不到 2 px 時不判粗細，標「不可量測」。 |

|---|---|---|

| attr.italic_min_slant | 6 度 | 傾斜角超過此值才提示斜體 |
| attr.underline_offset | 基線下方 0.05 到 0.25 個字級 | 底線的位置範圍 |

### 3B.7 區域分類

**目的**　扣掉文字之後，把剩下的像素分成照片、插畫、形狀、表格區、背景。輸出是可以重疊的遮罩，不是互斥的方框。

為什麼要可重疊：一張照片上壓著字，右下角又蓋著一個色塊。照片元素應該是完整的矩形，不是被挖洞的碎片。所以每個元素有自己的遮罩，遮罩可以互相重疊，另外記「哪一部分被誰遮住」。

**做法**

1. **先蓋掉文字。** 文字筆畫範圍標為「已解釋」，暫時用周圍顏色填平。這只為了分類，不是最終的修補。
2. **估背景模型。** 找出頁面上面積最大、可以用單一顏色或平滑漸層描述的部分。同時從平坦處估出雜訊水準（照片高，截圖幾乎為零）。
3. **取前景。** 與背景模型的差異超過雜訊門檻的像素是前景，連通後成為候選區域。
4. **小模型補候選。** 文件型頁面用版面偵測模型 PP-DocLayoutV3（Apache-2.0；25 類，含圖片、圖表、印章、表格；輸出多邊形輪廓，見 research/layout.md）。海報型頁面（字壓在圖上、元素互相重疊）用通用分割模型 SAM 2.1（Apache-2.0，見 research/layout.md）。頁面屬於哪一型，看「非平坦背景佔頁面的比例」。
5. **模型只出候選，分類靠準則。** 沒有任何現成模型能直接輸出本產品需要的分類，也沒有任何版面模型的說明文件把海報列為訓練資料（見 research/layout.md 結論第 1 點）。所以每個候選區域都要算下表的特徵再分類。

| 特徵 | 怎麼算 | 照片 | 插畫 | 形狀 |
|---|---|---|---|---|
| 有效色彩數 | 顏色以雜訊為容差分群，數出涵蓋 95 % 像素要幾群。一段平滑漸層算一群。 | 多於 64 群 | 4 到 64 群 | 不超過 3 群 |
| 平坦面積比 | 局部變化低於雜訊門檻的像素比例 | 低於 40 % | 60 % 到 95 % | 高於 95 %，或可由漸層擬合 |
| 邊緣寬度 | 邊緣從 10 % 升到 90 % 的寬度 | 寬窄不一，多數超過 3 px | 一致，不超過 2 px | 一致，不超過 2 px |
| 紋理與雜訊 | 高頻能量 | 高 | 低 | 低 |
| 輪廓規則程度 | 輪廓能被直線與圓弧擬合的長度比例 | 低 | 中 | 高於 90 % |

   補充規則：
   - 表格區由 3B.10 處理，它會先認領格線與對齊的文字。
   - 背景就是背景模型本身，加上佔滿頁面的底圖。
   - 尺寸小、色彩少的交給 3B.9 判斷是否為小圖示。
   - 色彩平坦、有矩形外框、內含大量小字的，記為圖片類型「截圖」。
   - 都判不出來的，記為圖片類型「其他」。子類型判錯不影響可編輯性，因為它們都是圖片。
6. **補全被遮住的外形。** 可見部分加上遮擋物，若能填滿外接四邊形的大部分，就認定它原本是完整的矩形（或圓角矩形、橢圓）。被遮住的範圍記入被遮擋紀錄。
7. **記遮擋關係。** A 的邊界在 B 的範圍內被打斷，而 B 的邊界連續，就是 B 在上。成對記錄，交給 3C.1。
8. **中間區。** 分數落在兩類之間時，先問圖片類型分類器（候選是 Docling 的 DocumentFigureClassifier，權重為 MIT 或 Apache-2.0；它的完整類別清單沒有對照官方模型卡，見 research/layout.md，需查證）。仍不確定才請大型 AI 在固定清單中選標籤。

**輸入與輸出欄位**　輸入：工作影像、全部文字的筆畫遮罩、品質遮罩。輸出：每個區域的遮罩（可重疊）、類型、特徵值、被遮擋紀錄、成對遮擋證據；背景模型（類型、參數、雜訊水準）。

**信心值依據**　各特徵離門檻有多遠；演算法與小模型是否一致；區域大小；是否落在品質遮罩的問題區內。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 翻拍印刷品，網點讓純色塊看起來有紋理 | 依品質遮罩的網點週期先平滑，再算特徵。 |
| JPEG 壓縮雜訊讓色彩數暴增 | 色彩分群的容差跟著雜訊水準調整。 |
| 照片裡的大片天空或白牆被當成背景或形狀 | 與照片主體相連、交界沒有清楚邊緣的，併回照片。 |
| 相鄰兩張圖被併成一張 | 沿直線邊緣切開，SAM 的遮罩輔助。 |
| 陰影被當成獨立元素 | 緊貼某元素單側、深色、邊緣極軟的，記為該元素的附屬陰影，修補時一併擦除。 |
| 漸層背景上的淺色塊偵測不到 | 背景模型改用漸層擬合後再取差。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| region.color_count_photo | 多於 64 群 | 照片的有效色彩數下限 |
| region.color_count_shape | 不超過 3 群 | 形狀的有效色彩數上限 |
| region.flat_ratio_photo | 低於 40 % | 照片的平坦面積比上限 |
| region.flat_ratio_shape | 高於 95 % | 形狀的平坦面積比下限 |
| region.edge_width_sharp | 2 px | 銳利邊緣的寬度上限 |
| region.min_area | 頁面面積的 0.01 % | 小於此面積的候選交給 3C.2 |
| region.poster_threshold | 50 % | 非平坦背景佔頁面超過此值視為海報型 |
| region.amodal_fill | 85 % | 補全外形所需的填滿比例 |
| region.layout_model、region.segment_model | PP-DocLayoutV3、SAM 2.1 | 候選來源模型 |
| region.ai_enabled | 開 | 中間區是否問 AI |

**可單獨升級的點**　① 長期路線：以 RT-DETRv2 或 D-FINE（皆 Apache-2.0）為底，用 DocLayNet（CDLA-Permissive-1.0）加上自己標註的海報與簡報資料，訓練出符合本產品分類的模型（見 research/layout.md 結論第 6 點）。② 圖層分解模型 LayerD（Apache-2.0，原始庫已封存）與 Qwen-Image-Layered（Apache-2.0，會重新生成像素）只當實驗對照組，不進主流程（見 research/layout.md、research/image.md）。

### 3B.8 圖內文字歸屬

**目的**　落在圖片範圍內的文字有兩種。一種是設計者打上去的版面文字，應該抽出來變成可編輯文字。另一種是圖片本身的內容：照片裡的招牌、截圖裡的介面文字、圖表的刻度。分錯的代價很高：把招牌擦掉重打，圖就毀了；把標題留在圖裡，就不能編輯。

**做法**　對每一行中心落在圖片類區域內的文字，看下列線索：

| 線索 | 像版面文字 | 像圖片內容 |
|---|---|---|
| 方向 | 與頁面水平或垂直對齊 | 跟著照片的透視傾斜 |
| 筆畫顏色 | 整行完全均勻 | 帶光影，雜訊與照片本身相當 |
| 邊緣銳利度 | 比照片主體銳利 | 與照片主體相同 |
| 與圖外文字的關係 | 字級、顏色、對齊位置與圖外文字一致 | 自成一格 |
| 所在圖片的類型 | 照片、純色塊 | 截圖、圖表、標誌、印章、條碼 |
| 是否跨出圖片邊界 | 可能跨出 | 不會 |

規則：

- 圖表、標誌、印章、條碼、QR 碼、截圖裡的字，預設留在圖裡。
- 照片上的字依線索計分。高分是版面文字，低分是圖片內容，中間區請大型 AI 回答二選一。
- 仍無法決定時，預設「留在圖裡」。理由：留錯了只是不能編輯，外觀不變；抽錯了會動到圖片本身，而且是生成。還原度報告要標示「此圖內有幾行文字未抽出」，使用者可用修正單改判。
- 留在圖裡的文字仍保留在 ElementList，內容可供搜尋與替代文字。它的歸屬指向該圖片；3B.12 與 3B.13 不擦除它。

**執行順序。** 這一步只需要 3B.3 與 3B.4 的結果。實際執行時排在 3B.5 之前，3B.5 與 3B.6 只對判為版面文字的行執行，省下不必要的計算。

**輸入與輸出欄位**　輸入：文字行（四角、遮罩、顏色）、3B.7 的區域遮罩與類型。輸出：文字行的歸屬；圖片的內含文字清單；歸屬分數。

**信心值依據**　各線索是否一致；所在圖片類型的信心值；經 AI 判斷者來源類型記「AI」。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 簡報裡一整張截圖的字被全部抽出 | 截圖類型預設留在圖裡。 |
| 海報主標題壓在照片上，卻被留在圖裡 | 字級大、與頁面對齊、顏色均勻的給高分。仍錯就靠修正單。 |
| 圖片類型本身判錯 | 3B.7 被修正後，本步驟跟著重跑。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| embed.score_high | 0.7 | 高於此分視為版面文字 |
| embed.score_low | 0.3 | 低於此分視為圖片內容 |
| embed.default_when_unsure | 留在圖裡 | 無法決定時的預設 |
| embed.always_embedded_types | 圖表、標誌、印章、條碼、QR 碼、截圖 | 這些類型內的字一律留在圖裡 |
| embed.ai_enabled | 開 | 中間區是否問 AI |

**可單獨升級的點**　圖表升級成可編輯圖表時（見 3B.9），圖表內的文字跟著抽出。

### 3B.9 特殊元素

**目的**　有些東西既不是一般文字，也不是一般圖片。預設一律當成圖片，但要標對類型。標對了，後面的階段與還原度報告才能正確對待它，未來也才能個別升級。

**做法**

| 類型 | 怎麼找 | 預設處理 | 未來能否升級成可編輯物件 |
|---|---|---|---|
| QR 碼、條碼 | 用解碼器直接偵測並解出內容。 | 圖片。另存解碼內容與碼的規格。 | 能，而且可以做到精確：用解出的內容重新產生向量的碼，再與原圖逐格比對確認。建議最先做。 |
| 印章 | 高彩度的紅或藍、圓形或方形外框、框內有字、常壓在文字上。版面模型有印章類別（見 research/layout.md）。 | 圖片，透明底。用顏色分離把印章與底下的文字拆開，兩者都保留。 | 不升級。對應 R8。 |
| 簽名 | 單色手寫筆跡，常在文件尾端或簽名欄旁。 | 圖片，透明底。 | 不升級。對應 R8。 |
| 手寫字（批註、填寫的內容） | 筆畫粗細不規則、基線不齊、辨識分數低。 | 圖片，透明底。辨識出的內容只當替代文字。 | 能：描成向量筆跡，或辨識成文字。PP-OCRv5 官方列有手寫支援（見 research/ocr.md），準確度需實測。 |
| 圖表 | 版面模型的圖表類別；有座標軸、刻度、圖例。 | 圖片（原生 PDF 為向量圖組）。內部文字留在圖裡。 | 能：轉成資料表，再輸出成原生圖表。PaddleOCR 有圖表轉表格的模組（見 research/layout.md 3.2 第 19 條）。數值屬於推論，要標「AI 判斷」。 |
| 標誌 | 小而精緻、含變形文字、常在角落。是否跨頁重複由④判斷。 | 圖片。內部文字留在圖裡。 | 部分：色彩平坦的可描成向量圖，但仍是一張圖，不是可編輯形狀。 |
| 小圖示 | 尺寸小、色彩少、邊緣銳利。 | 圖片，透明底。 | 能：描成向量圖。位於行首、與文字等高的，另加提示「可能是項目符號」，由④判斷清單。 |
| 公式 | 版面模型的公式類別；上下標密集、含特殊符號。 | 圖片。 | 能：轉成數學式語法，再輸出成 Office 方程式。屬於推論。 |
| 浮水印 | 見 3B.6。 | 圖片或文字，另標「浮水印」。 | 由使用者決定保留或移除。 |
| 核取方塊、表單欄位框 | 成列的小方框，旁邊有文字。 | 形狀，加提示「可能是表單欄位」。 | 能：升級成表單控制項，屬於⑥。 |

補充說明：

- **解碼器。** 候選是 OpenCV 內建的 QR 碼偵測（OpenCV 本體為 Apache-2.0，見 research/image.md）與 ZXing 系列函式庫。這兩者的條碼功能與授權不在本次查證範圍內，需查證。
- **印章的顏色分離。** 印章是單一顏色的印泥，蓋在紙與黑字上。把每個像素的顏色拆成「紙、黑字、印泥」三種成分，就得到印章的覆蓋率圖（當透明底圖片）與去掉印章後的底。黑字的筆畫由 3B.3 的遮罩保留。
- **R8 的處理。** 簽名與印章永遠不向量化、不升級、不美化，只保留原貌。類型標籤會傳給後面的階段與平台的濫用防護。

**輸入與輸出欄位**　輸入：3B.7 的區域遮罩與特徵、工作影像、文字行。輸出：圖片的類型、解碼內容、透明遮罩；提示旗標（可能是項目符號、可能是表單欄位）。

**信心值依據**　條碼與 QR 碼解得出內容，幾乎就是確定。其餘依分類器分數、幾何規則是否吻合、AI 的回答。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 印章與文字重疊，分離不乾淨 | 另保留一份未分離的原貌裁切，由⑥選用。 |
| 紅色標題字被當成印章 | 必須有封閉外框才算印章。 |
| 簽名與手寫批註難分 | 兩者都是圖片，類型錯的影響小。兩者都不升級，直到使用者指定。 |
| QR 碼殘缺，解不出來 | 依外觀（三個定位方塊）標類型，解碼內容留空。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| special.barcode_enabled | 開 | 是否偵測條碼與 QR 碼 |
| special.seal_min_saturation | 40 % | 印章顏色的最低彩度 |
| special.icon_max_size | 頁寬的 3 % | 小圖示的尺寸上限 |
| special.never_upgrade_types | 簽名、印章 | 永不升級的類型 |
| special.ai_enabled | 開 | 類型難分時是否問 AI |

**可單獨升級的點**　上表最後一欄的每一項都是獨立專案，互不相依。

### 3B.10 表格區與格線

**目的**　找出表格在哪裡，以及看得到的線。列欄結構與合併儲存格是④的工作。

這一步排在形狀向量化之前。格線先被表格區認領，3B.11 就不會把它們再描成一堆線段。

**做法**

有框線的表格：

1. **抽出長直線。** 在扣掉文字的影像上，沿水平與垂直方向找連續的細長墨跡。每條線記端點、粗細、顏色、樣式（實線、虛線、雙線）。
2. **找線網。** 互相交叉的橫線與直線連成網。至少兩橫兩直且有交點，就是表格區候選。只有橫線的表格（三線表）：至少三條等長的平行橫線，且線間的文字成欄對齊。
3. **取四角。** 線網的外接四邊形。

無框線的表格：

4. **找對齊線索。** 取所有文字行的左緣、右緣、中心，找出在多列重複出現的位置，這些是欄的對齊線。欄與欄之間有上下貫通的空白帶。至少兩欄三列，而且各列的基線跨欄對齊，才成為候選。
5. **交替的底色帶**（一列深一列淺）是列的線索，記入底色帶。
6. **輸出隱含對齊線。** 空白帶的中線位置，附上支持它的文字行編號。它不是看得到的線，種類要標清楚，不能與實線混在一起。

小模型與原生 PDF：

7. 版面模型的表格類別提供候選框，與演算法互相印證。兩者不一致就降信心值。無框表格候選的信心值中等時，請大型 AI 回答「這個編號的區域是不是表格」。
8. 原生 PDF 用同一套規則，輸入改成 3A.4 讀到的向量線與 3A.3 的文字位置。這條路準確而且可重現（見 research/layout.md 第 4 節第 4 點）。

表格區是候選，不是定論。④可以不採用。

**輸入與輸出欄位**　輸入：扣掉文字的工作影像、文字行的四角與基線；原生 PDF 改用向量線。輸出：表格區的四角、格線清單、區內文字行、底色帶、有框或無框。

**信心值依據**　線網的完整程度（實際交點數 ÷ 應有交點數）；每條對齊線被幾列支持；演算法與版面模型是否一致。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 兩欄內文被當成無框表格 | 表格的各列跨欄基線對齊、儲存格短；內文兩欄的行數不同、行很長。用「跨欄基線對齊比例」把關。 |
| 圖表裡的格線被當成表格 | 該區已被 3B.9 標為圖表，就不建表格區。 |
| 表單（方框多，但不成規則網格） | 照樣輸出表格區與線，由④決定。 |
| 照片裡的線微彎或斷續 | 容許小角度偏差；共線且間隙小的斷線接起來。 |
| 虛線被當成一串短線 | 先做共線合併，樣式記為虛線。 |
| 文字底線被當成格線 | 3B.6 先認領底線。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| table.min_line_length | 頁寬的 3 % | 短於此長度不算格線 |
| table.max_line_thickness | 頁寬的 0.5 % | 粗於此值視為色塊，不算線 |
| table.angle_tol | 1 度 | 偏離水平或垂直的容許角度 |
| table.gap_join | 線粗的 3 倍 | 斷線間隙小於此值就接起來 |
| table.min_rows、table.min_cols | 3 列、2 欄 | 無框表格候選的最小規模 |
| table.align_tol | 字級的 30 % | 視為同一條對齊線的容許偏差 |
| table.row_align_min | 80 % | 跨欄基線對齊比例的下限 |
| table.river_min_width | 1 個字級 | 欄間空白帶的最小寬度 |

**可單獨升級的點**　加第二個表格偵測模型交叉驗證。Table Transformer 的偵測模型是 MIT 授權，但原始庫已封存、最後更新在 2023 年（見 research/layout.md）。

### 3B.11 形狀向量化

**目的**　把形狀類區域變成可編輯的幾何。能認成基本幾何，就不用任意路徑。使用者拿到「一個圓角矩形」可以直接改圓角；拿到「四十個控制點的路徑」就不行。

**做法**

1. **範圍。** 只處理 3B.7 分為形狀的區域，並扣掉已被認領的（格線、底線）。
2. **取輪廓。** 由區域的覆蓋率遮罩取亞像素輪廓。
3. **由簡到繁逐一擬合。** 順序是：線 → 矩形 → 橢圓（含圓）→ 圓角矩形 → 多邊形（三角形、箭頭等）→ 任意路徑。採用「殘差在容許範圍內的最簡單模型」。殘差有兩個：輪廓到模型的最大偏差；把模型畫回去後與遮罩的重疊比例。
4. **空心或實心。** 遮罩中間有洞，且內外輪廓平行等距：只有線條、沒有填色。線寬等於內外輪廓的距離。
5. **線。** 記端點、線寬、樣式（沿線有週期性缺口是虛線）、端點形狀（端點有三角形墨塊是箭頭）。
6. **填色。** 純色取區域內顏色的中位數。顏色沿某個方向或某個中心平滑變化的，擬合成線性或放射漸層。兩者都不合，這個區域就不算形狀，改當圖片。
7. **不透明度。** 形狀同時壓在兩種不同的底上時，可以由兩處的顏色解出不透明度與本色。只壓在單一底色上時解不出來：半透明的黑壓在白上，與不透明的灰看起來一樣。這時記為不透明，並標「不透明度不可觀測」。
8. **任意路徑。** 用 VTracer（MIT，能處理彩色，有 Rust、Python、WebAssembly 介面）或自建的輪廓加曲線擬合。不用 Potrace 與它的各種移植版：它們是 GPL；另有付費的 Potrace Professional，價格未公開（見 research/image.md 1.4）。
9. **陰影。** 3B.7 記下的附屬陰影掛在形狀上，參數是估計值。

**輸入與輸出欄位**　輸入：形狀類區域的遮罩與顏色、背景模型。輸出：形狀的路徑（基本幾何與參數，或任意路徑；附擬合殘差）、填色、線條、不透明度、陰影。

**信心值依據**　擬合殘差；最佳模型與次佳模型的殘差差距；區域的解析度（小形狀的邊緣像素佔比高，較不準）；被遮擋的比例。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 矩形被文字或其他元素遮住一部分 | 用看得到的邊擬合。至少三個角可見才認矩形。 |
| 透視殘餘讓矩形變成梯形 | 小角度偏差內仍記為矩形，四角照實記。 |
| 圓角半徑很小，與直角分不出來 | 半徑小於門檻當直角。 |
| 手繪風格、邊緣有紋理 | 殘差大，改任意路徑；節點太多就改當圖片。 |
| 兩個相接的同色形狀連成一塊 | 在輪廓的凹角處嘗試拆成兩個基本幾何，拆不開就當多邊形。 |
| 形狀上有光澤等漸層以外的效果 | 改當圖片。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| shape.fit_tol | 頁寬的 0.1 % 與 1.5 px 取大者 | 輪廓到模型的容許偏差 |
| shape.min_overlap | 97 % | 畫回去後與遮罩的最低重疊比例 |
| shape.rect_angle_tol | 1.5 度 | 仍算矩形的角度偏差 |
| shape.min_corner_radius | 2 px | 小於此半徑當直角 |
| shape.max_polygon_vertices | 12 個 | 超過就改任意路徑 |
| shape.max_path_nodes | 200 個 | 超過就改當圖片 |
| shape.gradient_fit_tol | ΔE 4 | 漸層擬合的容許色差 |

**可單獨升級的點**　常見簡報圖形（連接線、流程圖符號、對話框）的辨識庫。每一種基本幾何是獨立的擬合器，可以逐一增加。

### 3B.12 圖片擷取

**目的**　把照片、插畫與特殊元素裁成獨立的圖片，外形正確，上面不帶版面文字。

**做法**

1. **像素來源。** 預設從工作影像裁。若原圖在該區的解析度高於工作影像，就經由「原圖到工作影像的轉換」回原圖重新取樣，少一次取樣損失。
2. **四角與拉正。** 圖片有旋轉時，四角照實記，裁切影像拉正後存放。
3. **外形。** 用 3B.11 的擬合器擬合區域輪廓。矩形、圓角矩形（記半徑）、橢圓：存「矩形影像加外形參數」，輸出時可用軟體原生的「圖片裁成形狀」。其他外形：存透明遮罩。
4. **被版面文字蓋住的部分。** 把 3B.8 判為版面文字的筆畫遮罩外擴，當作修補範圍，用 3B.13 的同一套修補器補回。這是生成，圖片元素要記「生成區域」。留在圖裡的文字不動。
5. **被其他圖片或形狀蓋住的部分。** 看不到的內容無從得知，不憑空生成。以邊緣顏色簡單延伸填滿，記入生成區域與被遮擋紀錄。輸出後這部分本來就被上層元素蓋住。
6. **透明底。** 簽名、印章、小圖示、標誌，以覆蓋率遮罩當透明通道。
7. **儲存。** 照片類存高品質的有損格式；插畫、截圖、帶透明底的存無損格式。來源本來是 JPEG 且沒有修補過的，不重新壓縮。
8. **實際解析度。** 裁切影像的像素數除以四角在頁面上的實際尺寸。

**輸入與輸出欄位**　輸入：圖片類區域（遮罩、類型、被遮擋紀錄）、工作影像、原圖與轉換、版面文字的筆畫遮罩。輸出：圖片的四角、裁切影像、外形與透明遮罩、實際解析度、生成區域、內含文字。

**信心值依據**　四角的邊緣擬合殘差；外形的擬合殘差；生成區域佔圖片面積的比例；修補的品質估計（見 3B.13）。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 照片邊緣與背景顏色接近，邊界找不準 | 用整條邊做直線擬合，不逐點判斷。低信心時邊界向外取。 |
| 圖片帶邊框或陰影 | 邊框記成圖片的線條屬性；陰影記成附屬陰影。 |
| 白底的去背商品圖放在白色背景上 | 邊界不可觀測。取墨跡的外接矩形，透明底。 |
| 字佔了圖片很大面積，要修補的範圍過大 | 生成比例超過上限就不修補，該文字改判為留在圖裡，加旗標請使用者決定。 |
| 回原圖取樣時，原圖該區失焦或反光 | 依品質遮罩加旗標。不做生成式放大。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| pic.resample_from_original | 開 | 原圖解析度較高時回原圖取樣 |
| pic.max_generated_ratio | 30 % | 生成區域佔圖片面積的上限 |
| pic.photo_quality | 95 | 照片類有損壓縮的品質（滿分 100） |
| pic.alpha_types | 簽名、印章、小圖示、標誌 | 以透明底存放的類型 |

**可單獨升級的點**　① 前景主體去背模型。② 修補器可獨立更換（與 3B.13 共用）。

### 3B.13 背景修補

**目的**　把文字、圖片、形狀都拿走之後，補回一張乾淨的底圖。靈感模板市場要的就是這張底圖。現有產品的已知弱點正是底圖留下文字殘影（見 research/market.md 4.1）。

這一步是生成類工作，是「量測歸演算法」的明列例外。生成的每一塊都要記錄。

**做法**

1. **等遮罩到齊。** 版面文字的筆畫、圖片、形狀、特殊元素、格線、附屬陰影，全部到齊才開始。
2. **決定背景類型。** 依 3B.7 的背景模型：

| 背景類型 | 判斷 | 表示方式 | 要不要生成 |
|---|---|---|---|
| 純色 | 沒被遮住的背景像素可用單一顏色描述，殘差在雜訊內。 | 參數式：一個顏色。不存影像。 | 不需要。來源類型「量測」。 |
| 漸層 | 可用線性或放射漸層描述。 | 參數式：漸層參數。 | 不需要。來源類型「量測」。 |
| 紙張 | 接近白色，帶掃描雜訊、紙紋或輕微泛黃。 | 參數式：紙色。另可保留原貌影像。 | 依使用者意圖。檔案急救預設當成空白頁，不留紙紋。 |
| 影像 | 照片、花紋、材質。 | 修補後底圖。 | 需要。來源類型「生成」。 |

3. **影像類背景的修補分級。**

| 級 | 適用 | 方法 | 工具與授權 |
|---|---|---|---|
| 1 | 遮罩周圍是平滑色或漸層 | 用周圍像素擬合局部的顏色曲面，填回去。 | 自己寫的演算法。 |
| 2 | 細筆畫，周圍變化平緩 | 傳統修補（由邊界向內擴散）。 | OpenCV 內建 Telea 與 Navier-Stokes 兩種方法，Apache-2.0（見 research/image.md 2.1 第 7 條）。 |
| 3 | 紋理、照片、大面積 | 修補模型。 | 首選 MI-GAN：程式碼與權重都有 MIT 明文授權；解析度 512 px，大圖要切塊。LaMa 的品質公認較好，程式碼是 Apache-2.0，但權重授權沒有明文，需法務確認後才可使用（見 research/image.md 1.3、3.3）。 |

   預設不用擴散式模型：它會重新生成像素，可能補出假文字（見 research/image.md 1.3）。不用 PatchMatch 的實作：Adobe 的專利狀態未明（見 research/image.md 2.4 第 44 條）。
4. **擦除範圍。** 筆畫遮罩外擴幾個像素，蓋住反鋸齒的邊與壓縮造成的暈。照片輸入擴得多一些。
5. **不同遮罩不同待遇。** 文字底下要認真補：新的文字不會與舊筆畫完全重合，補不乾淨就露出殘影。不透明的圖片與形狀底下簡單補即可（第 1 級）：這裡平常被蓋著，使用者移動元素時才會露出。
6. **切塊。** 模型修補以方塊為單位，只處理含遮罩的方塊，帶一圈周邊脈絡，接縫處羽化。
7. **擦除後再偵測。** 對修補後的底圖再跑一次文字偵測。還偵測得到字，就是沒擦乾淨：外擴加大後重做，次數有上限。
8. **記錄。** 生成區域遮罩逐像素標示：原始、演算法擬合、傳統修補、模型修補。逐區記方法、模型版本、品質估計。
9. **品質估計。** 四項：遮罩邊界內外的顏色與變化是否連續；殘留文字檢查的結果；遮罩的寬度（細的容易，寬的難）；周圍的複雜程度。

原生 PDF 不做這一步，見 3A.6。

**輸入與輸出欄位**　輸入：工作影像、全部元素的遮罩、背景模型、使用者意圖。輸出：背景類型、參數式表示、修補後底圖、生成區域遮罩與逐區紀錄、殘留文字檢查結果。

**信心值依據**　信心值依品質估計的四項。生成面積佔頁面的比例另記，供還原度報告使用。

**常見失敗與對策**

| 失敗 | 對策 |
|---|---|
| 文字殘影 | 擦除後再偵測；外擴加大。 |
| 補出來的區塊比周圍「太乾淨」（掃描與照片有雜訊） | 第 1 級填補後，加上與周圍強度相同的雜訊。 |
| 模型在規則花紋（格子、條紋）上補歪 | 花紋有明顯週期時，改用週期延伸的演算法。 |
| 模型補出不存在的物體 | 不用擴散式模型。大面積遮罩降信心值，並在還原度報告標示。 |
| 切塊接縫 | 重疊羽化，並做接縫檢查。 |
| 元素移走後留下影子 | 附屬陰影的遮罩一併擦除。 |
| MI-GAN 在文件底圖上的品質沒有資料（見 research/image.md 查不到的事第 7 項） | 自建測試集實測，需查證。 |

**設定檔參數**

| 參數 | 預設值（初始值） | 說明 |
|---|---|---|
| bg.dilate | 截圖 1 px；掃描 2 px；照片 3 px | 擦除範圍的外擴量 |
| bg.flat_fit_tol | ΔE 3 | 判為純色或漸層的容許色差 |
| bg.inpaint_model | MI-GAN | 第 3 級的修補模型 |
| bg.tile_size | 512 px | 模型修補的方塊邊長 |
| bg.tile_context | 64 px | 方塊外帶的脈絡寬度 |
| bg.max_retry | 2 次 | 擦除後再偵測的重做上限 |
| bg.paper_as_blank | 檔案急救開；靈感模板關 | 紙張類背景是否當成空白頁 |
| bg.noise_match | 開 | 填補後是否加上相同強度的雜訊 |
| bg.diffusion_enabled | 關 | 是否允許擴散式模型 |

**可單獨升級的點**　修補器的介面只有「影像加遮罩進、影像出」。可換成法務確認後的 LaMa，或用自有資料重訓的模型。使用者明確要求「重繪被遮住的複雜背景」時才啟用擴散式模型（FLUX.2 klein 4B、Qwen-Image-Edit 的權重為 Apache-2.0，見 research/image.md 1.3），並在還原度報告另外標示。

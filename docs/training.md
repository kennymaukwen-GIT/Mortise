# 訓練工廠：你的評價怎麼被記住、這一版算不算一個「模型」、怎麼讓它變強

這份是寫給不寫程式的人看的。怎麼放樣本、怎麼跑評測、怎麼寫標準答案，請看 [accuracy-loop.md](accuracy-loop.md)；
這裡講的是「回饋存在哪」「模型是什麼」「三種變強的方法」以及「現在做得到和還做不到的」。

## 一句話

**Mortise 的「模型」＝規則＋門檻＋模型檔，每一個組合有一個固定的版本名字；每個版本都有一張成績單；
你的每一次修改和評價都會留下來，累積夠多之後可以用三種方法讓它變強，而新版本要在成績單上贏過舊版本才採用。**

---

## 一、你每次的修改與評價存在哪

| 你做了什麼 | 存在哪 | 會不會被覆蓋 | 多久後刪除 |
|---|---|---|---|
| 改了字、字型、字級、顏色、對齊、角色、頁面尺寸、拖了紙張四角（**修正**） | 那份工作的目錄 `jobs/<工作編號>/job.json` 的 `corrections` | **不會**：你的修正信心值固定是 1.0、標成「鎖定」，之後不管重跑幾次、系統升級幾次，都不會被系統的判斷蓋掉 | 30 天 |
| 打分數（1–5）、勾標籤（字認錯了、字型不對…）、寫意見、回報某個東西有錯（**評價**） | `jobs/<工作編號>/feedback/` 每次一個檔 | 不會（每次新增一個檔，不改舊的） | 30 天 |
| 上傳時勾了「同意用於改善辨識」 | 上面兩樣**另外**收一份到回饋庫（`MORTISE_FEEDBACK`，預設 `jobs/_feedback/samples/`）：原始檔＋同名的 `.feedback.json` | 不會 | **不會自動刪**（這是你同意保存的資料） |

- **同意開關**：只有上傳時勾了「同意用於改善辨識」的檔案，才會進回饋庫、才會被拿去評測、調參、訓練。沒有勾的，只存在工作目錄裡，30 天後連同原始檔一起刪掉。
- **30 天**：保留天數由 `MORTISE_RETENTION_DAYS` 設定（預設 30）。目前是在**伺服器啟動時**清掉過期的工作（見下面「還不能做到」）。
- **收進回饋庫時記了什麼**：你改了什麼、改成什麼，以及**系統當時給的值和它有多少把握（信心值）**。後者是「校準」的原料：系統說九成把握的東西，你到底改了幾成。
  改一行字時，記的是那一整行的字（不是只有第一個樣式段）和文字辨識的信心值（原生 PDF 擷取出來的字是精確的，記 1.0）。
- **自己的資料，自己帶走**：可以下載「回饋包」（`<原檔名>.mortise-feedback.zip`，網頁「檔案」選單的「匯出這份工作的回饋」，
  API 是 `GET /api/jobs/{id}/feedback/export`），**不需要**勾同意。裡面有：
  - `sample/<原檔>`：你上傳的檔案；
  - `sample/<原檔主檔名>.feedback.json`：你的評分、修正、標籤與意見（格式 `mortise.feedback/1`，說明在 `mortise/eval/feedback.py` 開頭）。
    修正記著系統當時的值與信心值（2026-11-28 以前、沒勾同意的工作沒有記下，列在 `snapshot_missing`）；
    「這個東西是對的／有錯」記著那個東西當時的信心值（匯出時從工作目錄查出來）；
  - `report.json`：還原度報告；
  - `README.txt`：白話說明怎麼用。
- 想看某份工作已經送了哪些回饋：`GET /api/jobs/{id}/feedback`（列出每一筆評價、修正單數量、有沒有同意）。

把回饋包交給開發者，或自己收進回饋庫：

```bash
python -m mortise.eval feedback-import 季報.mortise-feedback.zip --store 回饋庫
```

- 同一份工作同時在回饋庫（勾同意後自動收的）和回饋包裡：同一筆修正、同一個「對／錯」只算一次（有信心值的那份優先）。
- 回饋包可能來自別人，所以收進來時會檢查裡面的工作編號、修正單編號與檔名（只准英數、減號、底線；不合格的丟掉或換成內容雜湊），
  寫檔前也確認路徑還在目標目錄底下，不會被一個做壞的回饋包寫到別的地方。

## 二、「模型」在 Mortise 是什麼

一般說的「模型」是一個訓練出來的神經網路檔。Mortise 不是只有一個網路，它是七個階段的流水線，
裡面大部分是**量測規則**（例如「行距超過一般行距的 1.4 倍就分段」），只有少數地方用到學習式的模型檔
（文字辨識 PP-OCR、彎曲紙張攤平的 UVDoc），而且照架構的鐵律，模型只能在候選中挑或給初值，數值一律由量測決定。

所以在 Mortise，**一個「模型」＝一個引擎版本**，由這幾樣組成，任何一樣變了，版本就變：

| 組成 | 是什麼 | 怎麼變 |
|---|---|---|
| 規則 | 七個階段的程式與各自的版本號 | 工程師改演算法 |
| 門檻 | 設定檔 `mortise/config/default.toml`（加上覆寫檔） | 自動調參、人工調整 |
| 模型檔 | 文字辨識（偵測、辨識、方向分類三個檔）、攤平用的 UVDoc | 微調文字辨識、換新版模型 |

版本名字長這樣（完整的字串是唯一的名字；後面括號是好記的短名，由完整字串決定）：

```
mortise-0.1.0+s1v3.s2v5.s3v3.s4v3.s5v6.s6v4.s7v6-cfg02f7ad68-ocrbbb248-uv753d-srcd4c618aa   （杉狐-42）
```

`s1v3…s7v6` 是七個階段的版本、`cfg` 是設定的指紋、`ocr` 是文字辨識模型檔的指紋、`uv` 是攤平模型的指紋（沒有下載是 `uvnone`）、
`src` 是程式碼的指紋（有人改了程式卻忘了改版本號，名字照樣會變）。短名只有 25600 種，版本多了會撞名
（累積 100 個版本時約 18% 的機會有兩個同名），所以**比較、存檔一律看完整的版本字串**，短名只是口頭方便。查目前的版本：

```bash
python -m mortise.engine          # 或網頁 API：GET /api/engine（另附最新成績單的摘要）
```

所以：**可以，你可以把「這一版」叫做一個模型，它就是那串名字。** 要「訓練成更強的模型」，就是用下面三種方法之一產生一個新名字的版本，
再拿成績單證明它比較強。它不會自己偷偷變：沒有人跑這些步驟，它就一直是同一個版本。

### 成績單：這個模型考幾分

成績單用固定的考卷：從 `tests/fixtures` 的虛構文件出題，用固定的亂數種子把每一頁做成截圖、掃描、平的手機照片、彎曲的照片，
每一題都跑完整的七個階段，答案就是原本的 PDF（所以不需要人工標答案）。記錄的分數：

- 文字錯字率（整頁，含漏字多字）、字級誤差（pt）
- ⑦驗證的總分，以及每個輸出格式（可編輯 PDF、PowerPoint、Word…）各自的分數
- 照片四角成功率（四個角都在對角線 1% 以內）、**四角錯了卻沒有請你確認的比例**（最危險的錯，應該是 0）
- 表格列數欄數是否正確、每頁處理時間

```bash
python -m mortise.eval scorecard --quick --out 成績單      # 快速版：10 題（時間見 docs/scorecards/README.md）
python -m mortise.eval scorecard --out 成績單              # 完整版：32 題
```

輸出 `成績單/<版本名>.json`（完整數字）和 `.md`（給人看）。目前引擎的基準成績單放在 [scorecards/](scorecards/)。
成績單也記下**考卷本身的指紋**（考卷檔，以及出題、評分程式的雜湊）：有人改了考卷或評分方式，分數會變，但那不是引擎變強或變弱。

**新模型要比舊模型好才採用**：

```bash
python -m mortise.eval scorecard compare 舊版本.json 新版本.json
```

- 總體和每一種輸入（截圖、掃描、照片、彎曲照片）各比一次，退步的數字用粗體標出；每個指標只用兩份都有這個指標的題目平均（比的一定是同一批題目）。
- 有幾項設了「不可退步」的門檻（錯字率、字級、⑦各格式分數、照片四角、表格、整頁變成圖片…），超過門檻就回報「不建議採用」。
- **新版本當掉不能當成沒事**：舊的有、新的沒有的題目（缺題）、同一題少了設門檻的指標（缺指標）、新出現的錯誤，都直接算超過門檻的退步。
  確定是故意的（例如故意拿掉某種題目）才加 `--allow-missing` 放行。
- 兩份的考卷指紋不同時，報表上用粗體警告；加 `--strict-exam` 時直接拒絕比較。
- 結束碼：沒有超過門檻的退步是 0、有是 1、檔案不對是 2、`--strict-exam` 而考卷不同是 3，之後可以直接接到自動檢查（CI）上。
- 門檻可以改：`--gate page_cer=0.005`、`--gate seconds_per_page=50%`、`--gate quad_success=off`。

## 三、三種「變強」

| | ① 校準信心值 | ② 自動調參 | ③ 微調文字辨識 |
|---|---|---|---|
| 改的是什麼 | 系統「對自己有多少把握」的數字（不改輸出） | 設定檔裡的門檻 | 文字辨識的模型檔 |
| 你會感覺到 | 該問你的地方才問你，不該問的不再煩你 | 分段、對齊、字級等判斷更貼近你的文件 | 字認得更準（特別是你常用的字型、拍照的情況） |
| 需要的資料 | 有「系統當時信心值」的資料，**而且要兩種都有**：你改掉或標錯的、你看過確認是對的。程式的門檻：至少 50 筆、至少兩個信心區間各 5 筆、兩種各至少 5 筆（這些是程式裡的保守下限，不是文獻數字；每個欄位要穩定建議幾百筆，需查證） | 樣本檔案（PDF 不需要標答案；照片要有標準答案或回饋）：建議先每類 20 份，之後每類 100 份（見 accuracy-loop.md） | 文字行影像＋正確文字。PaddleOCR 官方微調說明：字典不變時**建議至少 5000 張**文字行，改字典要更多；混入通用的真實資料時，每一輪你的資料和通用資料**約 1:1**（出處見下面第 2 步） |
| 指令 | `annotations` → `calibrate` | `tune` → `scorecard --config` → `compare` | `ocr-dataset` → GPU 機器上訓練 → `ocr-model` → `scorecard --config` → `compare` |
| 要多久 | 幾秒 | 每試一個值要把樣本從④重跑一次；整體時間沒有量過（需查證，樣本數與輪數越多越久） | 準備資料約 2 分鐘（見下面）；訓練要 GPU，時間需查證；這台開發機沒有 GPU，不能訓練 |
| 現在能不能做 | 算得出校準表，**還沒有自動套回流水線**；網頁的元素面板有「這個是對的」按鈕，要累積夠多「對」與「錯」才建得出表（見下面） | 可以 | 資料與放回去的步驟可以；訓練要另外的 GPU 機器，步驟沒有實測 |

### ① 校準信心值

```bash
python -m mortise.eval feedback-import 回饋庫/samples --store 回饋庫/store   # 或匯入回饋包（.zip）
python -m mortise.eval annotations --store 回饋庫/store --out 標註.jsonl
python -m mortise.eval calibrate 標註.jsonl                 # 全部一起
python -m mortise.eval calibrate 標註.jsonl --stage 3 --field text   # 只看③的文字
python -m mortise.eval calibrate 標註.jsonl --field element          # 元素層級（網頁上每個東西旁邊的信心值）
```

**為什麼要兩種資料**：校準是在問「系統說九成把握的東西，實際上對幾成」。如果只收到你改掉的（全部都是錯的），
程式會以為「不管系統多有把握都是錯的」，把所有信心值都校成 0；只收到對的也一樣。所以要同時有「你看過但沒改」的資料
（「這個是對的」，或看過一整頁沒改）。只有一種時程式會直接拒絕，說「選擇偏差」，不會硬算。

資料不夠時也會直接說「樣本不足：只有 N 筆，至少需要 50 筆」。下面幾種不算進校準：沒有記下系統當時信心值的修正
（例如較早、沒勾同意的工作，回饋包裡列在 `snapshot_missing`）、「同一個欄位第二次改」（那時的值是你上一次改的，不是系統的判斷）。
拖四角時，你的四角和系統自動找到的四角差在容許範圍內（`within_tolerance`，例如直接按「套用」），算成「看過、沒改」；
同一頁第二次以後拖四角，和第一次比的是同一個系統判斷，不重複算。同一頁評了好幾次分，以最新一次為準。

### ② 自動調參

```bash
python -m mortise.eval tune 樣本目錄 --out 調參結果 --variants screenshot,photo
python -m mortise.eval scorecard --config 調參結果/override.toml --out 成績單
python -m mortise.eval scorecard compare 成績單/舊版本.json 成績單/新版本.json
```

調參只會在 `mortise/config/tunable.toml` 列出的範圍裡找，並保留四分之一的樣本當驗證（避免只對這批樣本有效）。
`compare` 沒有超過門檻的退步，再把 `override.toml` 的數值抄進 `default.toml`（這時版本名字的 `cfg` 那段會變，就是一個新模型）。

### ③ 微調文字辨識（PP-OCR）

**第 1 步：產生訓練資料（這台機器就能做，已實測）**

```bash
# 從原生 PDF 自我監督（PDF 裡的字就是答案）＋你改過的字
python -m mortise.eval ocr-dataset --out 訓練資料 --from-fixtures --pdf 你有權使用的PDF目錄 --from-feedback 回饋庫/samples
```

- **原生 PDF**：把每一頁畫成影像，加上截圖、掃描、翻拍的干擾，用 PDF 文字層的字與位置把每一行裁下來。
  - 翻拍的頁面先畫成 300 dpi 再拍（真實手機照片裡的字比 150 dpi 大很多；用 150 dpi 翻拍出來的字太小又糊，人眼也讀不出來）。
    行高太小的行（照片低於 20 像素、其他低於 10 像素）略過。
  - 旋轉、直排的字（例如海報側邊的直排字）整串略過，不會切成一字一行配上正立的答案。
  - 2026-11-28 實測：`tests/fixtures` 的 13 份虛構文件產生 **1436 行**（四種干擾各 359 行），約 **114 秒**（同時有別人在跑，負載 4 到 8）；
    驗證集 144 行（10.0%）。照片那一組行高中位數 28 像素、低於 24 像素的佔 19%。每種干擾抽 80 行丟回目前的文字辨識讀：
    錯字率 乾淨 0.001、截圖 0.001、掃描 0.020、照片 0.008（裁切和答案對得上，照片也看得清楚）。
  - 這些文件字型種類少，單靠它練不出更強的模型，主要是用來補量、穩住原本的能力。
- **你的修正**：你在網頁上改字（網頁送的是「段落」）、或直接改③讀到的某一行，都會被收進來，從那份工作的影像裁出那一行，答案用你改的字。
  - 段落有好幾行時，程式把你改後的整段字和系統原本每一行的字對齊，**換行處沒被你改動、切得開的行才收**；切不開的（例如你改的字剛好跨在兩行之間）
    記在 `manifest.json` 的 `skipped`，寫明原因。你改了其中一行時，同一段裡沒改的行也會收進來（你看過、沒改，當成對的），`line_changed` 標出哪一行是改過的。
  - 一行超過 25 個字（PaddleOCR 的辨識設定檔 `max_text_length` 是 25，超過的訓練時會被丟掉；A4 中文一行常有 30 到 40 個字）時，
    **切成幾段短的**：用③量到的每個字的位置決定在哪裡切，只在你沒改動的地方切（你改的字不會被切成兩半），
    每段裁好後再用目前的辨識模型讀一次，和系統原本在那一段讀到的字比，字錯率不超過 0.2 才收（證明裁切框住的就是那幾個字）。
    切不成的記在 `skipped`。2026-11-28 端對端實測：網頁上改了一個 39 個字的中文行裡的一個錯字，切成 25 字＋14 字兩段，
    改過的那段標 `line_changed: true`，兩段都通過重讀檢查。
  - 只收**勾了同意**的；回饋包裡沒勾同意的、或同意狀態不明的（例如自己做的回饋包），要加 `--include-unconsented` 才收（確定是你自己的資料時）。
  - 工作目錄 30 天後刪除，但回饋庫和回饋包裡有原始檔，會自動重跑一次流水線把那一行找回來（同一個引擎版本才找得到）。
- **輸出**：`images/`、`rec_gt_train.txt`、`rec_gt_val.txt`（每行「圖片路徑＋Tab＋文字」，PaddleOCR 的格式）、`dict.txt`（目前模型的字典，18708 個字）、
  `out_of_dict.txt`（**目前的模型字典裡沒有、所以永遠認不出來的字**）、`manifest.json`（每一筆從哪來、有沒有經你同意、授權、每種干擾的行高分佈）。
  驗證集依頁切（同一頁的行不會分到兩邊），並依「行數」逼近要的比例。

**第 2 步：在有 GPU 的機器上用 PaddleOCR（Apache-2.0）微調辨識模型（沒有實測）**

下面的檔名與指令是 2026-11-28 對照 PaddleOCR 在 GitHub 上的檔案與官方文件寫的，**沒有在 GPU 上實際跑過**；版本不同時請再確認。

1. 安裝 PaddlePaddle（GPU 版）與 PaddleOCR 原始碼（`git clone https://github.com/PaddlePaddle/PaddleOCR`，`pip install -r requirements.txt`）。
   PaddlePaddle 與 PaddleOCR 的版本要互相對得上（需查證）。
2. 下載**和 Mortise 現在用的同一個**辨識模型的「訓練用權重」（`.pdparams`，不是推論用的檔）。Mortise 用的是 rapidocr 內附的 PP-OCRv6 small 辨識模型：
   它的字典和 PaddleOCR 的 `ppocr/utils/dict/ppocrv6_dict.txt` 一字不差（都是 18708 個字），設定檔是 `configs/rec/PP-OCRv6/PP-OCRv6_small_rec.yml`。
   官方文件（`docs/version3.x/module_usage/text_recognition.md` 的模型表）列了它的訓練模型 `PP-OCRv6_small_rec_pretrained.pdparams`；
   這個檔沒有下載驗證過，與 rapidocr 內附的 ONNX 是不是同一組權重也需查證。
3. 改設定檔：`Global.pretrained_model` 指到第 2 步的權重；`Global.character_dict_path` 用第 1 步的 `dict.txt`
   （**字典要和模型一致**；要加 `out_of_dict.txt` 裡的字，就得改字典，模型最後一層會重新訓練，需要更多資料）；
   `Train.dataset.data_dir` 設成「訓練資料」目錄、`label_file_list` 用 `rec_gt_train.txt`；`Eval` 用 `rec_gt_val.txt`。
   官方建議：載入預訓練權重時學習率要調小，並依批次大小等比例調整。
   - 資料量與混合比例出處：PaddleOCR `doc/doc_ch/finetune.md`（release/2.7 分支）。
     3.1 節「不更換字典的情況下，建議至少準備 5000 張的文本識別數據集」；
     3.3 節「如果有通用真實場景數據加進來，建議每個 epoch 中，垂類場景數據與真實場景的數據量保持在 1:1 左右」（用 `ratio_list` 控制）。
     同一份文件 3.1 節的「原始數據與新增數據比例 10:1～5:1」講的是「只有部分字元認錯、補一批特定字元資料」的情況，不是一般的混合比例。
4. 訓練：`python3 tools/train.py -c configs/rec/PP-OCRv6/PP-OCRv6_small_rec.yml -o Global.pretrained_model=./PP-OCRv6_small_rec_pretrained.pdparams`
   （多張 GPU：`python3 -m paddle.distributed.launch --gpus '0,1' tools/train.py -c …`）。官方文件的範例是 PP-OCRv5 server，換成 v6 small 的設定檔是照同一個格式推的。
5. 匯出推論模型：`python3 tools/export_model.py -c 你的設定.yml -o Global.pretrained_model=output/…/best_accuracy.pdparams Global.save_inference_dir=./rec_infer/`
   （出處同上，text_recognition.md 4.4 節）。
6. 轉成 ONNX：`paddlex --install paddle2onnx` 之後 `paddlex --paddle2onnx --paddle_model_dir ./rec_infer --onnx_model_dir ./rec_onnx`
   （出處：`docs/version3.x/inference_deployment/others/obtaining_onnx_models.md`；paddle2onnx 是 Apache-2.0）。

**第 3 步：放回 Mortise（這台機器就能做，已實測）**

轉出來的 ONNX 沒有 Mortise 要的字典（Mortise 從模型檔的 metadata 讀字典）。這個指令把字典寫進去，並檢查「模型輸出的類別數 = 字典字數 + 2」，對不上就拒絕：

```bash
python -m mortise.eval ocr-model rec_onnx/inference.onnx --dict 訓練資料/dict.txt --out /固定的位置/mortise_rec_v2.onnx
```

它會印出換上的設定。先把這段寫進一個覆寫檔（例如 `new_ocr.toml`），給成績單用：

```toml
[recognize.ocr_params]
rec_model_path = "/固定的位置/mortise_rec_v2.onnx"
```

**第 4 步：考試，贏了才採用**

```bash
python -m mortise.eval scorecard --config new_ocr.toml --out 成績單
python -m mortise.eval scorecard compare docs/scorecards/<目前的版本>.json 成績單/<新版本>.json
```

新版本的名字 `ocr` 那段會變。`compare` 沒有超過門檻的退步才採用：

1. 網頁伺服器只讀 `mortise/config/default.toml`（不讀覆寫檔），所以把上面那兩行加在 `default.toml` 的 `[recognize]` 那一節後面
   （`[recognize]` 底下不能已經有 `ocr_params` 這個鍵）；
2. 重新啟動伺服器（伺服器啟動時才讀設定檔）；
3. 把新成績單放進 `docs/scorecards/` 當下一次的基準。

成績單的考卷是合成的；換 OCR 這種大改動，最好再用回饋庫裡的真實照片跑一次 `python -m mortise.eval run`（見 accuracy-loop.md）。

## 四、現在能做到與還不能做到的

**能做到（有測試）**

- 修正鎖定、不被覆蓋；評價逐筆保存；同意的才進回饋庫；回饋庫不跟著過期。
- 網頁 API：查一份工作的回饋（`GET /api/jobs/{id}/feedback`）、下載回饋包（`GET /api/jobs/{id}/feedback/export`）、查引擎版本與最新成績單（`GET /api/engine`）。
  網頁上的評分、回報錯誤、拖曳四角、匯出回饋包由另一位開發者接上（這份文件不涵蓋網頁的細節）。
- 引擎版本：規則、門檻、模型檔任何一樣變了，名字就變。
- 成績單與比較（含「不可退步」門檻、缺題與新錯誤也擋、考卷指紋、結束碼）；目前引擎的基準成績單在 `docs/scorecards/`。
- 回饋 → 標註 → 校準表（只有一種資料時拒絕）；自動調參；OCR 訓練資料（自我監督＋你在網頁上改的字）；把微調好的模型放回並檢查。
- 不受信任的回饋包不會把檔案寫到目標目錄外面。

**還不能做到**

- **「這個是對的」要你主動按**：網頁的元素面板（「修正」模式點一個框）有「這個是對的」按鈕（2026-11-28 加上）。
  你不按，系統只收到「有錯」的資料，校準會因為選擇偏差拒絕建表；也還沒有「整頁看過都對」的一鍵確認。
- **校準表還沒有套回流水線**：現在只能算出「系統說九成把握時實際對幾成」，系統給你的信心值還是原本的。
- 2026-11-28 起，不論有沒有勾同意，每筆修正連同系統當時的值都會存一份在工作目錄（`feedback/corrections.jsonl`），匯出的回饋包就有系統當時的值；
  勾了同意、自動收進回饋庫的「這個是對的／有錯」也會記下那個元素當時的信心值。更早的工作沒有這份快照（回饋包裡列在 `snapshot_missing`），不能拿來校準。
- 30 天刪除：伺服器啟動時清一次，之後每 6 小時再清一次（`MORTISE_PURGE_HOURS` 可以改）。
- **沒有真的訓練過 OCR**：這台機器沒有 GPU；PaddleOCR 的訓練、匯出、轉 ONNX 步驟都還沒實測，訓練用權重也沒有下載驗證。
- **成績單的考卷是合成的**：真實照片的光線、鏡頭變形不在裡面；每種輸入只有一到幾題，一題錯分數就差很多。
- **換 OCR 模型要改 `default.toml` 並重新啟動伺服器**：伺服器不讀覆寫檔。（成績單、評測工具用 `--config` 換模型時，同一個程式裡會依設定重新載入模型。）
- 字型檔、LibreOffice 的版本、大型 AI 服務端的更新不算在引擎版本裡（它們會影響結果，但版本名字不會變）。

# 「系統先讀完、不確定處反黃問使用者、不規則圖形自己畫框」功能設計（主持人定，待前端與描圖兩條線完成後開工）

創辦人原話：「系統以及 ai 會先讀完整份檔案，會在辨識不清楚或不理解的地方用反黃（淡黃色、低透明度）的方式問使用者那是什麼，或要定義成什麼；或者是不規則圖形時，可以讓使用者自己畫他的圖框。」

## 流程
1. 按 CONVERT → 流水線照常跑完（成品先出來，使用者不必等問答才有檔案）。
2. 系統由各階段的信心值與問題產生「問題清單」；大黑框（輸入翻閱）在對應位置畫淡黃色半透明螢光筆效果（例：填色 rgba(255,230,90,0.28)、邊緣稍深），每頁顯示有幾題。
3. 點黃色區域 → 小視窗問「這是什麼／要定義成什麼」，給選項（系統的候選；有 AI 時標出 AI 建議）、可自由輸入、可「維持原樣」。
4. 不規則圖形或系統漏掉的區域：使用者用畫框工具（矩形、多邊形逐點、手繪套索）自己圈，並指定它是什麼。
5. 回答累積後按「Apply」→ 一次送出成修正單（使用者修正 confidence 1.0，之後重跑不會被覆蓋）→ 只從受影響的階段重跑 → 結果更新、黃色變成已回答。
6. 問題是建議性的：不回答也能下載。

## 問題種類 → 修正單
| 種類 | 何時問 | 選項 | 修正單 |
|---|---|---|---|
| text | 文字行信心低、或有字的候選很接近 | 目前讀法、候選讀法、自由輸入 | 既有 text（⑤） |
| kind | 圖片或區域的類型信心低（照片／插圖／形狀／表格分不清） | Text、Photo、Illustration→向量、Shape、Table、Logo、Background（忽略） | 新：③ kind（element_id） |
| region | 有墨跡卻沒被任何元素認領、或背景修補處不確定 | 同上 | 新：③ region（多邊形＋種類） |
| outline | 形狀擬合誤差大、或描圖沒通過（不規則圖形） | 使用者畫或調整外框 | 新：③ outline（element_id＋多邊形） |
| size | 頁面尺寸判斷 ambiguous | 尺寸候選、自填 | 既有 size（②） |
| role | 標題／內文等角色不確定 | 角色清單 | 既有 role（④） |
| （使用者主動）draw | 使用者自己圈任何區域 | 同 kind | 新：③ region |

座標：修正單裡的多邊形用頁面相對座標（頁寬 = 1，原點左上，y 向下），與產物一致；API 負責換算。

## 後端
- 新模組 mortise/questions.py：只讀各階段產物，產生問題清單（不寫產物）；每題有穩定編號、頁碼、位置（多邊形）、問題文字、選項、目前值、信心值、要寫成哪種修正單。
- 有 AI 時：每題請 AI 在選項中挑一個建議（鐵律 4：只在候選中選），標 ai_suggestion；沒有 API 金鑰時不顯示。
- ③要能吃新修正單：kind（改元素類型並照新類型重做：Text→區域內跑文字辨識；Illustration→描圖；Photo→不描；Background→併入底圖；Table→表格偵測）、region（使用者圈的區域照指定類型處理，優先於自動結果）、outline（用使用者的多邊形當形狀或描圖的遮罩）。
- API：GET /api/jobs/{id}/questions、POST /api/jobs/{id}/answers（批次，轉成修正單並重跑）。

## 前端
- 黃色螢光標示層、問題小視窗、問題清單（第幾題／共幾題、上一題下一題）、畫框工具（矩形、多邊形、套索；可拖點調整）、Apply 與重跑進度、已回答狀態。
